# 同人音声（シチュボイス）執筆ガイド（仮）

## 新方針（2026-05 追記・仮運用）

以下は、同人音声レビューを「催眠適性評価」ではなく、**音響作品としての設計評価**へ寄せるための仮ルール。正本へ統合する前提で本ファイルに先行記載する。

**フォーマット参照方針（重要）**  
記事の**見出し構造・段組・配置ルール**は、`docs/真催眠音声執筆ガイド.md` のうち**同人レビューへ無理なく転用できる項目だけ**を参照する。  
一方、催眠固有の規定（誘導手続きの評価語、催眠特有の評価軸・用語、催眠前提の断定）は同人レビューへ持ち込まない。

### 総合の星（`ratingValue`）による口調（最重要）

フロントマターの **`ratingValue`（総合 ★／10）** で YAML とタイトル周りの**口調義務**を切り替える。

| 帯 | 口調・YAML の正 |
|----|------------------|
| **★9〜10** | **ナデナデ解剖どおり**（読者へのねじれフック・熱量のあるカード）。下記「参照できる項目」の **★9〜10 列** をすべて適用する。 |
| **★8 以下** | **`futarigake-saimin-dry-iki-support/index.md`** の **構成説明口調**に寄せる（同人でも **`ratingValue` は同人の総合 ★**）。`**--その〇〇へ、`** でねじれを売らない。**説明的な `summary`／`itemDescription`** でよい。 |

### `summary` の★分岐（禁止・必須・見本・適用範囲）

**適用範囲（重要）** … 次の★分岐は **`summary`・`itemDescription`（YAML）** と **`### 基本情報` の `タイトル導入：`** にのみ適用する。**`## パート解説`・グラフ評価内訳・総評など、本文のパート解析ブロックは `ratingValue` だけで口調や構成を変えない**（別節のルールどおり執筆する）。

**★8 以下（構成説明型・ドライイキ準拠）**

- **語尾** … 「〜になっています」「〜する構成です」「〜まで完結させる構成です」など、**手順・帯・終端・ミックスが追える説明**で閉じる。
- **`summary` で禁止** … **`--その〇〇へ、`**（半角ハイフン二連の矢印）。**`──その欲求へ`** のようにダッシュで「その〜へ」を立てる型。**「〜したい層へ」「〜層へ、」**だけでターゲットを先に置き、本文の設計説明が続かない広告調。
- **見本** … `src/content/レビュー/futarigake-saimin-dry-iki-support/index.md`（YAML の `summary`）。

**★9〜10（ナデナデ型・カード熱量）**

- **`summary` での必須寄り** … **ねじれ／両立したい欲求**を短文で提示し、**`--その〇〇へ、`** で本作の応答に接続してから、**観測できる構成の事実**で締める（ナデナデの `--その矛盾へ、` と同型）。
- **見本** … **催眠：** `warui-inma-kanashiki-koufuku-nadenade-hagu`。**同人シチュ：** `dakimakura-kanojo-pretty-holic-yurukawa-kouhai`。**★10 の同人**でも総合がハイ帯なら同型でよい（例：`levelup-onasapo-dungeon`）。
- **再発防止（★9〜10 共通）** … `summary` で **耳疲労・聴き疲れなど購入前に不安だけを断定**しない（ねじれは試聴・再生で検証できる設計論へ）。詳細は上記「読者への矢印」 bullet。

**催眠音声レビューとの関係** … ★閾値と `summary` 口径は **`docs/真催眠音声執筆ガイド.md` §2「総合の星による `summary` 口径」**および **`docs/レビュー執筆・採点運用ガイド.md` §4a** と**同一**（同人／催眠で星の意味は異なるが、**カード `summary` の義務の切り替えは同じ**）。

**参照できる項目（採用）**

- **`title`・`itemName`・`【レビュー】`** … `docs/真催眠音声執筆ガイド.md` §1（補）項1 と同じ役割分担。**サイト用 `title` に `【レビュー】` を前置してよい。**`itemName` は販売ページの商品名のまま。**催眠固有の語は使わず**、プレフィックスと役割分担だけ転用する。
- **`### 基本情報` の並び** … **`主題:` は一行必須**（§1（補）項2 と同型）。  
  - **`タイトル導入：`（★9〜10・★8以下とも一行必須）** … **★9〜10**：`warui-inma-kanashiki-koufuku-nadenade-hagu` と同型。**関係／演出の軸**→タイトル由来の**具体手段**→**機能または時間軸**→「**構成を示すタイトルです。**」で締める。**★8 以下**：同じく設計宣言で締めるが、**煽り・呼びかけは抑え**、`futarigake-saimin-dry-iki-support` の **`タイトル導入：`** のような**冷静な構成説明**に寄せる。  
  - **`タイトル語の読み（本作における断定）：`** … 「〇〇は、…を指します／機能しています」の**定義型**。両帯で必須。  
  - **読者への矢印（`summary`）** … **★9〜10 のみ**：購入意欲は **`summary`** で `--その〇〇へ、` のように**内的欲求／不安を一文で言い切ってから**接続する（ナデナデの `--その矛盾へ、` と同型）。必要なら `itemDescription` を二段落にして**前半工程／後半工程**を分ける。**★8 以下**：**義務なし**。**`--` を使わず**、帯・手順・終端・ミックスが追える**説明文**で締める（ドライイキ見本）。**禁止（両帯共通）：** 「タイトルから読み取れるだけ」の空虚な言い換え。**★9〜10 の再発防止：** `summary` で **「耳が疲れる」「聴き疲れで買う気が削げる」型の不安を先に断定**しない。ねじれは**没入が途切れる／定位や関係の段差がボヤける**など、**再生後や試聴で検証できる設計論**に寄せる。
- **タイトル・パッケージ語の断定** … 同ガイド §2 項4。煽り語・タイトル各語が「本作では何を指すか」を、`summary` のいずれかの段落、または **`## 作品概要`・`## 総合評価`・パート解説** で**レビュアーの言葉で一文以上**述べる（同人では催眠技法語ではなく、**シチュ・関係性・音響・構成**で断定する）。
- 見出しの並び、`作品概要` / `総合評価` / `パート解説` / `総評：本作品の結論` のブロック設計（実用・同人レビュー寄せ）
- `おすすめしたい方` / `合わない可能性がある方` の 3:2 構成
- `パート別` の **引用 → 解析 → 第三段落** の順序  
  - **第三段落は次のどちらかで統一する**（混在は避ける）：  
    - **心身の反応** … 上級・熱量トーン（下記「分析→破壊」系）で用いる観測。  
    - **実用メモ** … **事実・実用特化**（下記「事実・実用性への特化」）ではこちらを標準とする。
- `## 総評：本作品の結論` を標準見出しとし、直下は三柱で締める。**見出し語の並び**は `### 【設計の要点】` / `### 【音響面の精度】` / `### 【結論】` をこの順とする（「（失敗しにくさ）」などの括弧付けラベルは付けない）。
- **記事末尾（同人レビュー・本ガイド準拠）** … `## パート解説` のあとに **`## 総評：本作品の結論`** だけを置き、**三柱のあとで本文終端**とする。**`## 作品感想`**・管理人挨拶・「良き同人音声ライフを👋」などは**置かない**（**催眠音声レビューのルート A（ラブハピ）**専用。同人とは構成が異なる）。**末尾ブロックの h2 はこの表記に固定**し、`作品の結論` の単独短縮や別名 h2 に置き換えない。

### タイトル周りの解剖（ `warui-inma-kanashiki-koufuku-nadenade-hagu` ／投稿時点の完成形）

**適用：** **`ratingValue` ★9〜10 のみ**がこの表をカード熱量の**正**とする。**★8 以下**は **`futarigake-saimin-dry-iki-support`** 型の説明文優先（`--` なし）。

| ブロック | 役割 | 見た目の型 |
|----------|------|------------|
| `summary`（★9〜10） | 読者の**ねじれ・欲求**を短く提示→`--`→**本作がどう応えるか**で締める | 「AなのにB」--その矛盾へ、… |
| `summary`（★8以下） | **構成・手順・終端**が読める**説明**で締める（ねじれの強調は不要） | 「〜を〜し、…になっています。」 |
| `itemDescription`（★9〜10） | **前半／後半**の二段落で工程が一目でわかる | 段落1＝受容・導線／段落2＝主軸・終端 |
| `itemDescription`（★8以下） | **同上でも単段落でもよい**。工程説明・バージョン差が伝わればよい | ドライイキ見本 |
| **`タイトル導入：`** | タイトルを**設計宣言**として読ませる（評論ではなく構成の約束） | 関係軸＋タイトル手段＋変換または一本軸＋「示すタイトルです」 |
| **`主題：`** | **フェーズの因果**が入った長文＋括弧で体裁（尺・一本道など） | 先に〜したあと、…し、…する構成（…の主旨） |
| **`タイトル語の読み`** | 煽り語を**本作における意味**へ一回で接地 | 「〇〇」は…を指す |

**同人への転用見本：** ★9〜10 … `dakimakura-kanojo-pretty-holic-yurukawa-kouhai`。★8以下 … **`futarigake-saimin-dry-iki-support`** の YAML／基本情報の**説明口調**（シチュボイスでも構成説明に寄せる）。

**参照しない項目（不採用）**

- 催眠の誘導技法を前提にした評価語・判定基準
- 催眠向け三軸の名称や運用
- 催眠レビュー専用の文脈（暗示適性を中心に置く説明）

1. **`summary`（YAML・カード直下）**  
   **`ratingValue` ★9〜10：** `docs/真催眠音声執筆ガイド.md` §2 の密度感に寄せる。**`--その〇〇へ、`** でねじれフック。**★8 以下：** §2「総合の星による口径」の**構成説明型**（ドライイキ見本）。**フック短文のみ**特例は★9〜10 側で評価。**文字数の目安だけ**を機械適用しない。

2. **基本情報・パート配分**  
   **`タイトル導入：` を一行必須**。**★9〜10** はナデナデ型の熱量。**★8 以下**は説明調。**`主題:` を一行必須**。パート表・総再生時間の出典括弧は従来どおり。**購入矢印（`--`）** は **★9〜10 のみ** `summary` で担う。**`itemDescription`** … ★9〜10 は可能なら**二段落**（前半／後半）。★8以下は**説明的**でよい。

3. **おすすめしたい方 / 合わない可能性がある方**  
   催眠への向き不向きではなく、**催眠音声レビューと同型**（`おすすめしたい方`→箇条書き3項目→`合わない可能性がある方`→箇条書き2項目）で次を軸にする。  
   - **おすすめしたい方**：箇条書き3項目（各項目は「太字で読者属性の1フレーズ」→改行→説明段落）。  
   - **合わない可能性がある方**：箇条書き2項目（同上。必要なら `**合わない人**` としてもよい）。  
   - **必須ルール：** おすすめ側3項目のうち、**少なくとも1項目はシチュエーション適性**（例：添い寝・同棲・お泊まり・主従・年上年下など）を明示する。  
   - **内容の軸（既定寄り）**：おすすめ側は「距離感の嗜好（超近接など）／演技の質感（リアル系・アニメ系）／音響の指向性」を優先、合わない側は「ノイズ耐性／特定シチュへの嫌悪／物語テンポとの不一致」を優先する。

4. **グラフ評価内訳（仮軸）**  
   既存の催眠寄り軸は使わず、次の三軸で記述する。  
   - **没入・臨場感（Presence）**：距離感の一定性、バイノーラル定位精度  
   - **音響設計（Acoustic）**：録音S/N比、効果音配置、パラ言語（声のトーン）  
   - **充足度（Satisfaction）**：脚本の着地、余韻の質  

   **表示フォーマット固定（重要）**  
   サイト表示で「グラフ評価内訳」の左線スタイルを維持するため、記事本文の軸見出しは次の語を使う。  
   - `- **没入度 n（距離感 n / 定位精度 n）**`  
   - `- **刺激度 n（録音品質 n / パラ言語 n）**`  
   - `- **満足度 n（着地 n / 余韻 n）**`  
   ※概念上は Presence / Acoustic / Satisfaction を採用しつつ、**表示キーは没入度／刺激度／満足度で固定**する。

5. **パート解説（フォーカス変更）**  
   誘導手続きの説明より、**音響演出の意図**と**演技の機序**を優先する。  
   - 解析で答える問い：なぜこのタイミングで耳元移動か／なぜこの効果音か  
   - **第三段落**  
     - **心身の反応（上級・熱量トーン）：** どの帯域が前景か、どの場面で情動の段が切り替わるか等、**観測語**で書く。生々しい身体反応の列挙に寄せすぎない。  
     - **実用メモ（事実・実用特化・既定寄り）：** 定位・ノイズ・台詞の聞き取りやすさ・長尺耐性・入眠前に使えるか等、**読者が同じ条件に近づけて試せる事実**に限定する（上記「事実・実用性への特化」）。

6. **総評：本作品の結論**  
   「誘導成功」ではなく、**音響作品としての設計精度**（録音・演技・脚本の整合）で締める。見出し・三柱の細則は本ファイル「`## 総評：本作品の結論`（上級・追記）」を参照。

### 特殊同人（探索型・分岐型オナサポ）運用（2026-05 追記）

`レベルアップ式オナサポダンジョン ～レベルを上げて最高の射精を目指す探索型オナサポゲーム～` の分析データで確定した、**ゲーム構造を持つ同人音声**向けの仮ルール。通常の「一本道トラック作品」と同じ書き方をすると、読者が誤解しやすい。

1. **レビュー冒頭で「作品の型」を先に宣言する**  
   - まず「探索型」「分岐あり」「失敗ルートあり」「到達レベルでエンディング変化」など、**体験の前提**を1〜2文で明示する。  
   - ただし本文で「攻略wiki」のように細かい手順を列挙しすぎない。**購入判断に必要な難易度情報**を優先する。

2. **パートの並べ方は「時系列」より「機能別」を優先する**  
   この型はファイル数が多いため、`## パート解説` は次の機能単位でまとめる（個別トラックは必要箇所だけ引用）。  
   - スタート地点（ルール説明）  
   - 中間地点（必須課題）  
   - レベリングルーム（任意課題・レベル加算）  
   - ゴール地点（最終寸止め・振り分け）  
   - クリア地点（レベル帯エンディング）  
   - 失敗時音声（暴発／ギブアップ・命令無視）

3. **「必須課題」と「任意課題」を混同しない**  
   - 中間地点のオナサポは**進行必須**。  
   - レベリングルームは**任意**だが、クリア時レベルに直結する。  
   - この区別を曖昧にすると、読者が「どこまでやれば作品の設計意図に乗るか」を判断できない。

4. **失敗系トラック（暴発・ギブアップ）を軽視しない**  
   - 失敗音声は蛇足ではなく、**緊張維持の装置**として評価対象に入れる。  
   - ただし「罵倒の強さ」だけで点数を決めない。  
   - 見るべきは、失敗時の文言が本編ルール（命令遵守・寸止め維持・再挑戦導線）と整合しているか。

5. **評価軸に「ルート設計の明瞭さ」を追加で見る**  
   既存三軸（没入／刺激／満足）に加えて、探索型では次を本文で必ず触れる。  
   - どこで分岐するかが分かるか  
   - レベル条件と到達先（例：クリア地点1〜4）の関係が読者に伝わるか  
   - 再挑戦時に迷子になりにくいか（ガイド音声・フォルダ導線）

6. **総合評価の根拠は「一本の最適ルート」前提にしない**  
   - 高レベル到達の快感だけを基準にせず、**通常到達・失敗到達の体験品質**も含めて評価する。  
   - 「完走難易度が高いほど高得点」という運用は禁止。  
   - 難しい作品でも、導線が不親切なら減点対象。

7. **おすすめ欄は「嗜好」だけでなく「運用適性」を入れる**  
   `おすすめしたい方` の3項目のうち最低1項目は、次のような**運用条件**を書く。  
   - ルール音声を聞いて段取りどおり進めるのが苦にならない  
   - 分岐・再挑戦を前提に反復プレイできる  
   - 失敗ルート込みで世界観を楽しめる  
   `合わない可能性がある方` には、短時間回収志向や手順読み飛ばし傾向を明示する。

8. **本文に入れない情報（メタ）の明確化**  
   - `info.txt` のアフィリエイトURL、クーポン有無、体験版有無は、本文に直書きしない（既存運用どおり）。  
   - 解析素材のファイルパス列挙も本文禁止。必要なら `_分析データ.json` の `notes` へ。

9. **この型での「パート第三段落」は実用メモ推奨**  
   - 通常作よりトラック本数が多く、読者は「どこで詰まるか」を知りたい。  
   - 第三段落は `心身の反応` より `実用メモ` を優先し、  
     - 失敗しやすい区間  
     - 休憩を挟むべき区間  
     - 再挑戦時の目印  
     を事実ベースで書く。

10. **`title` の `【レビュー】` 前置（サイト一覧・標準寄り）**  
    - **`title`** を **`【レビュー】＋商品タイトル`** とする（末尾に「レビュー」を再度付ける必要はない）。**探索型・一本道シチュボイスを問わず**これで統一してよい。  
    - **`itemName`** は販売ページの商品名を維持し、変更しない（真執筆ガイド §1（補）項1 と同じ）。

### 事実・実用性への特化（2026-05 追記・標準寄せ）

長尺シチュボイスや近接録音では、**読者が再現できない主観の羅列**より、**誰でも検証しやすい事実と実利**を優先する。`dakimakura-kanojo-pretty-holic-yurukawa-kouhai` 改稿で整理した次の3点を、同人レビューの**既定寄り**として扱う。

1. **「きもい」描写を客観的な事実へ**  
   - **避ける例：** 眼瞼下垂、特定筋の収縮、局所の生々しい反応の列挙など、医学・解剖に寄りすぎた身体ログ。  
   - **推奨：** **聴き疲れ・中断のしにくさ**、定位やミックスが**長尺でも破綻しにくい**ことなど、生活実感または耳で検証できる語。**自律神経・入眠**など幅広い生理語は、**パート名やタイトルが既に約束している内容の言い換え**にしない（→ 下記「タイトル・トラック名と重複する断言」）。  
   - **耳・機材側で書いてよいこと：** 帯域・定位・ノイズフロア・音量バランス・S/N（読み取れる範囲の事実ベース）。

**タイトル・トラック名と重複する断言は書かない（重要・完成度に直結）**  
**入眠用／安眠／リラックス**など、販売側が既に書いている効果を、そのまま繰り返して段落を終えない。**読者が怖い落差**（高刺激の直後の急転換、角の立つSE、名目だけのパート）を起点に、**音量・密度・編集・勾配**など音声の事実で、タイトルやトラックリストの**約束と実装がつながっているか**を書く。実例の書き分けは `dakimakura-kanojo-pretty-holic-yurukawa-kouhai` の **007【安眠用】** の `実用メモ` を参照。

2. **「上から目線」をユーザー視点のメリットへ**  
   - **避ける例：** 「〜を評価する」「完成度が高い」とだけ断言する**評論者スタンス**。  
   - **推奨：** **試聴条件を明示**したうえでのチェックリスト調。**長時間でも姿勢・音量で続けられるか**、**販売ページの総再生時間（例：162分）に対してタイトルどおりの流れが薄まらないか**、環境ノイズに弱い耳でも破綻しないか、など**購入前に知りたい項目**で書く。  
   - **グラフ内訳**の見出しは、現行フォーマットでは **`グラフ内訳`** を既定とする。必要がある場合のみ補助ラベルを追加する。

3. **「そそる」表現を、音響・物理の確信へ**  
   - **避ける例：** 誘惑・煽りだけで終わる形容。  
   - **推奨：** **音響のノイズが目立たない**、**定位がトラックをまたいでもブレにくい**、**終盤で刺激を落とし入眠導線がある**など、**再現性のある品質の事実**で「失敗しにくい」と読者に伝える。

**パート解説の第三段落（実用メモ）で書くことの例：** 左右定位の一貫性、台詞の前景の保たれ方、休憩を挟む目印になる区切り、**本編から終盤への落差が編集・帯域・音量でどう処理されているか**（「安眠だから眠れる」の繰り返しではなく、約束と実装の噛み合い）、など。

## 分析→破壊のサイクル（黄金パターン・任意）

長編シチュボイスで **論理で構えて快感で壊す**ときの推奨フロー。正本の同名節と内容は対応させ、**詳細はこちらを参照**。  
**★9〜10** での熱量レビュー向け。**★8 以下**では原則使わず、**構成説明・実用メモ**で足りる。  
**注意：** **事実・実用性への特化**で書く回では、敗北・毒性・無様な渇望の強調は**必須にしない**。同じ実例ファイルでも、トーンは企画・読者層で切り替える。

1. **構築** … 声道・帯域・交感／副交感・性的勾配など、読める範囲で論理を立てる。
2. **ミクロ官能** … **特定キャストの一拍の呼吸・吐息**で刺す。キャスト名＋**決め台詞の直後**が効きやすい。
3. **刺激度で崩壊** … 理屈が続かない瞬間を明示する。続けて **シャットダウン後の無様な主観**を一行（例：分析が **「もっと聴かせろ」と喉だけが騒ぐ渇望**に落ちる）。**交感が最高だった区間**と**言語が崩れたトリガー**も書く。
4. **満足度** … 約束の回収に加え、**期待の質の変質**。**現実へ戻る手順が浮かばない毒性**。それでも **翌日また再生する**不可逆を一文。
5. **感想** … 「設計図への敗北」より、**仕事が手につかない／責任の所在／理性が快感に破壊された**など生々しく。**執筆時の身体ノイズ**（吐息が残りキーが慎重になる等）を一行。

**実例：** `src/content/レビュー/dakimakura-kanojo-pretty-holic-yurukawa-kouhai/index.md`（随時更新）

## `## 総合評価` の書き方（上級・追記）

正本「`## 総合評価` の書き方（同人専用）」に**加える**ときのメモ。

- **事実・実用特化** … 見出しは `## 総合評価` を固定し、直下は星評価から開始する。必要なら補助ラベルを置けるが、現行実例では **`**グラフ内訳**`** を標準とする。
- **星の根拠** … 「約束どおり」だけに寄せない。**その音声で管理人がどう溶けたか**を軸語に寄せてよい（**実用特化の回では**「ページの約束が尺のせいで薄まらなかったか」等、読者メリットで書く）。
- **没入度** … 脚本の整合に加え、**現実の部屋をいつ・どこで忘れたか**をミクロに。
- **刺激度** … 勾配の理屈のあと、**本能側への落下**を必ず一行。
- **満足度** … 約束回収だけにしない。**放心・多幸感の重さ・毒性・再生依存**まで踏み込めるなら踏む。

## `## パート解説`（上級・追記）

正本「`## パート解説`」に**加える**ときのメモ。

- **事実・実用特化** … 見出しは **`## パート解説`** を標準とする。第三段落は **`実用メモ`** で統一し、定位・ノイズ・長尺・終盤の帯域／情報密度など**検証可能な事実**に寄せる（新方針「事実・実用性への特化」）。**パート名との効果の言い換えだけ**で終えない（「タイトル・トラック名と重複する断言」節）。

- **キャストに固執** … 抽象の音響語より、**決め台詞のあとの一息・吸気**を拾う。
- **スタンス** … 見出し直下に一言、**演技論よりひれ伏し側のログである**と置いてよい。

## 禁則・ダメ例（ワークショップ）

| NG | 理由 |
|----|------|
| 「正直に言います」「マジで」「ずるい」「距離感バグ」の連発だけ | 安いエモのパッチワークに見える。 |
| 「ディスプレイが視界に入らない」だけ | 定型で読み飛ばされる。ミクロな錯覚を優先。 |
| 「解析フォルダ」「文字起こし参照」など | 読者向けメタ。**`_分析データ.json` の `notes`** に限定。 |

| 「〜を評価した」「完成度は極めて高い」等、**根拠なしの評論者口調**だけ | 読者メリットが見えない。**試聴条件＋チェック結果**で書く。 |
| 「挟みやすい」「入れやすい」「〜しやすいです」だけで文や段落を終える | **何を挟む／置く／基準にするか**が欠け、読者が操作や順序を復元できない。**休憩・分割再生・音量判断など、聴き手の具体動作**まで書く（`.cursor/rules/review-prose-voice.mdc` と `docs/真催眠音声執筆ガイド.md` §3e 項8 と整合）。 |
| **「主菜」** で構成や快感の軸を言う | 献立メタになりやすい。**軸・中心・土台・主眼・前景**で書く（§3e 項9・`review-prose-voice.mdc`）。 |
| 「いきなり尖らず」のような語感先行の表現で流れを説明する | 何がどう急にならないかが不明で読み手に解釈を委ねすぎる。**刺激・SE・帯域・会話テンポ**のどれを指すかを丁寧に書く（§3e 項10・`review-prose-voice.mdc`）。 |
