分析データ・尺・スタッフ名・購入リンクなどの**事実データは、筆者が別ファイルでまとめて渡す前提**とする。AIはそのデータを本文の適切な位置に埋め込み、**本ガイドと正本（kuchikou）の文体ルール**に従って執筆する。

## フロントマター（YAML）

正本（kuchikou）どおり、次を揃える。

| 項目 | 役割 |
|------|------|
| `slug` | URL・フォルダ名と一致する一意の ID |
| `title` | ページタイトル（作品名＋必要なら「レビュー」等） |
| `summary` | 一覧・OGP 用の短い紹介。**解析方法・タイムスタンプ・セグメント境界などのメタは書かない**（読者向けに作品の魅力・型を一文〜数文で。例：王道派・本格誘導・何を狙うか）。`itemDescription` も同様。正本は1段落の例。必要なら `\|` ブロックで段落を分けてもよい。 |
| `tags` | 催眠音声・属性タグなど（サイトの絞り込みに使う） |
| `ratingValue` / `ratingBest` | 星評価（通常は 10 点満点換算） |
| `itemName` / `itemDescription` | 構造化データ用（未入力時は summary 等にフォールバックしうる） |
| `authorName` | 著者表示 |
| `publishedAt` | `YYYY-MM-DD` |
| `coverImage` | 主ビジュアル URL または `/content/reviews/<slug>/...`（推奨・ASCII パス） |
| `coverAffiliateHref` | 任意。ジャケット画像クリック用 |
| `affiliateLinks` | 体験版・購入ボタン等（vendor / href / label） |
| `workImpressionAvatar` | 任意。**`## 作品感想`** 見出しの**直右**に、LINE のトプ画のような**丸アイコン**（いわゆるムキネコ等）を出す。`coverImage` と同じく **`/content/reviews/<slug>/ファイル名`**（ASCII パス）。PNG をレビューフォルダ直下に置き、`npm run sync:content-assets` で配信。本文に `![](同じURL)` を**書かない**（サイト側の `ReviewMarkdown` が見出し行に描画するため重複になる）。 |

画像・グラフは **レビューフォルダ直下**（`src/content/レビュー/<slug>/`）に置く。本文・HTML で参照する URL は **`/content/reviews/<slug>/ファイル名`** に統一する（英数字パスのみ）。`npm run dev` / `npm run build` の前に走る `sync-content-assets` が `src` 側の非 Markdown 資産を `public/content/レビュー/` にコピーし、**同じ内容を `public/content/reviews/` にもミラー**する。`/content/レビュー/...` のように **日本語フォルダ名を URL に含めると本番で画像が壊れる**ことがあるため、**必ず `reviews` 側を参照**すること。

## 本文セクション構成（この順で揃える）

正本（kuchikou）に合わせた標準構成。**Markdown ファイル上の並び**は次のとおり。

サイトでは `splitBodyAtFinalRating` により、**`## 総合評価` 見出しの直後から、次の `## `（h2）直前まで**が「総合評価」欄用の `rating`、**その次の `## ` から下**が `rest` になる。

さらに `splitRatingAtWorkIntroLabel` により、`rating` 内の **`### 作品解説と感想` 行の直前**で分割される。**星・価格・注記・区切り線まで**が「総合評価」ブロックの**左列**と、横の**体験版ボタン**（`affiliateLinks` があるとき）が**同じ段**に並ぶ。`### 作品解説と感想` 見出しと、その直下に書く短文（あれば）は**その下の段**に表示され、**スマホでも体験版ボタンが「作品解説と感想」ラベルの下に落ちない**。`## 作品像` は引き続き `rest` の先頭。

1. **`## 作品名`** … 太字でフルタイトル1行。直後に `---`。
2. **`## 作品概要`**
   - `### 基本情報` … サークル・種類・CV・シナリオ・イラスト等（渡されたデータを箇条書き）
   - `### 収録の長さ（パッケージ表記より）` … 正本の見出し。**短く揃えたい場合**は `### 収録の長さ（パッケージ）` でも可（補助参照の kyoku はこちらの短い形）。本編・派生トラックの尺を箇条書き。
   - `### パートの長さ（目安）` … 次の**いずれか**に揃える（混在可）。
     - **四区分型（正本・催眠向けの標準）** … 先頭に **導入 → 暗示 → エッチ → 解除** などへの分け方を一文で示し、**`- **パート名** — 約 0:00–4:43（短い説明）`** をフラットに並べる。境界はトラック名・台詞の転換・無音の変化などから決め、**見出しに「解析データによる」などのメタは付けない**（目安で十分）。
     - **トラック番号型（kyoku 補助参照）** … `- **01** 短いタイトル — 6:22` のように、**番号・タイトル・時間（分:秒）**を1行ずつ。
     - **ネスト型（futarigake 補助参照）** … 本編合計の下にトラックごとをインデントした箇条書き。
   - 必要なら1行メモ（例：絶頂シーン数）… 見出しが不要ならプレーンテキスト1行でも可
   - **`### 聴取時の身体反応（心拍）`（任意）** … Polar H10 等で心拍ログを載せるとき。配置は **`### パートの長さ（目安）` の直後、`### 作品評価グラフ` の直前**を推奨。**グラフ画像の直前の導入文は、下記「生体ログ・心拍グラフの固定文」に定めた1文を一字一句そのまま使う**（言い換え・追加・削除をしない）。その直後に画像（レビューフォルダ直下・ASCII ファイル名推奨、参照は `/content/reviews/<slug>/...`）、続けて**波形の読み**（時間帯ごとの傾向、主観の身体感覚、副交感神経／交感神経、必要なら bpm の帯など）を作品ごとに執筆する。`summary` に数値や測定手順のメタを書かないルールは維持する。
   - **`### 作品評価グラフ`** … レーダー等の画像1枚。`![作品評価グラフ（トランス度・快楽度・満足度）](/content/reviews/<slug>/review_triangle.png)` のように書く（見出しに「アイアン・トライアングル」等の別名は**不要**でよい）。**三軸の数値・グラフ生成**は `src/content/レビュー/<slug>/_分析データ.txt` に記載し、`python scripts/generate_review_triangle.py <slug>` で PNG を出力 → `npm run sync:content-assets` で反映。定義は `docs/レビュー三軸評価定義.md` に従う。三軸の1行説明は正本のように **満足度＝興奮のあとの収束と安心感** でも、他レビューで使っている **安らぎと体験の収束** でもよい（サイト統一したいときは揃える）。
   - ブロックの終わりに `---`
3. **`## どんな人におすすめか`** … 箇条書き＋**合わない人**を1行で明示。**催眠音声初心者向けに適している**場合は、先頭付近に **`**催眠音声初心者の方**`** のような1行を入れてよい（正本どおり）。
4. **`## 総合評価`** … 見出し直後に **`**★n／10**`**（**`★10／10` はサイト側で赤系に強調表示**される）。続けて任意で **価格・クーポン・体験版**などを箇条書きし、価格・キャンペーンの変動に関する注記を付けてもよい（正本の並び・トーンを参照。金額は作品ごとに差し替え。販売ページに「記載時点の表記」と書きたい場合は補助参照の futarigake 等を参考にしてよい）。横並びの **「作品ページはこちら」**は `affiliateLinks` があるとき自動表示。
5. **`---`** … 任意。星・価格のあとで区切りたいときに入れる（正本どおり）。
6. **`### 作品解説と感想`** … **`## 作品像` の直前に必ず置く**ラベル見出し（h3）。`## 作品像`（h2）より一段軽い階層で、**作品像〜パート解説〜作品感想**へ続く塊の見出しであることを示す。中身の段落は通常なく、**すぐ次行を `## 作品像`** にしてよい。サイトでは **星・価格・ボタン行の直下**にこの見出しが来る（上記 `splitRatingAtWorkIntroLabel`）。
7. **`## 作品像`** … **読者を物語に引き込む総論**。テンポの変化は「一定ではない」だけにせず、**どのパートでどう変わるか**を具体的に書く。分割後は **`rest` の先頭**になり、区切り線の下の本文ブロックから始まる。**催眠・誘導の専門語は「全体の設計がわかる」程度に混ぜる**（下記「催眠技法・専門性の織り込み方」）。用語の見出し羅列はしない。
8. **`## パート解説`** … **正本の基本形**は `### 導入パート（約 0:00–4:43）` のように **パート名＋尺のみ**の小見出し。必要に応じて `### 暗示パート（約 4:43–22:18）── 逆カウントの本丸` のように **`── キャッチ`** を足してもよい（futarigake / kyoku の例）。
   - **引用と解説の固定形（必須）** … **`>` 引用ブロック1つ**の直後に、**その引用に対する解説**を必ず書く。**もう1つ引用する場合は、解説のあとに次の `>` を置く。** つまり並びは常に **「引用 → 解説 → 引用 → 解説 → …」**。同一パート内で **引用ブロックだけが2つ以上連続する**構成は避ける（画面上で灰色の引用箱が縦に積み上がり、読みにくくなるため）。
   - **1つの引用が複数行にわたる場合**だけ、`>` 行のあいだの空行は**同一ブロック内の段落分け**としてよい（そのブロック全体の直後に、まとめて1つの解説を書く）。**別の引用ブロック**を続けるときは、その前に**必ず解説の段落を挟む**（`>` と `>` のあいだに本文がないと、サイトによっては引用箱が縦に積み上がる）。
   - 台詞の引用は、可能な範囲で**作品の実際の文言**に寄せる（筆者メモ・解析テキストから転記）。
   - **技法名**（ペーシング、分割法、逆カウント、イメージ誘導、拮抗、アンカーリング、ラポール、トリガー、抑制、条件付けなど）は**解説の段落の本文に溶かして**使う。**パートの通称**（覚醒・後催眠・脱出・暗示など）は作品文脈で意味が通じることが多いので、**括弧の対象にしない**（下記「括弧は技法に」）。正本（kuchikou）では**分割法**などを太字で示し、**括弧で一言説明**を添える例や、「技法名で言えば〜だが、用語で飾るより〜」と**本筋を台詞側に戻す**書き方がある。**見出しで技法名を並べない**。教科書のように用語だけを並べず、**体感・場面の説明を主、用語は補助**（下記「催眠技法・専門性の織り込み方」）。**引用ルールを優先した結果、解説が短くなりすぎたパートでは、あえて技法名を1文足して専門性とわかりやすさのバランスを取ってよい。**
   - パート数が多い作品では、後半をまとめて書かず**節を省略**してもよい。
9. **`## 作品感想`** … 筆者の一人称・体験ベースでよい（正本のトーン参照）。**驚き・コスパ・特定の技法への言及**（例：再導入と「分割法」）もここでよい。**`## 総評` は置かず、この見出し（h2）だけ**でよい。旧来どおり **`### 作品感想`** だけでも可。サイト側では **`## 作品感想` と `### 作品感想` のいずれも** `splitRestAfterWorkImpression` で検出され、このブロック直後に購入ボタン等が挿入される場合がある。
   - **任意。** フロントマター **`workImpressionAvatar`** を付けると、見出し「作品感想」と**同じ行のすぐ右**に丸アイコンが付く（ムキネコ等。**正本・既存レビュー**も同様に利用可）。本文では画像 Markdown を重ねない。
   - ※グラフは**作品概要**側に置く（作品感想の下には置かない）

セクション間は `---` で区切る（正本に合わせる）。

### フロントマターの `affiliateLinks` と「総合評価」

- 本文に **`## 総合評価`** があり、かつ **`affiliateLinks` に1件以上**あるとき、レビュー詳細ページでは **「総合評価」見出しの横に体験版導線**（先頭リンクのラベルを **「体験版はこちら」** に差し替え）が並ぶ。ヘッダー近くの先頭リンクは **「作品ページはこちら」** に差し替え（用途が分かれる）。
- その場合、ページ下部の別枠「作品のページへ」は**出さない**（重複防止）。
- `## 総合評価` を消すと分割されず、従来どおり下部に「作品のページへ」だけ出る。
- 星の行以降も **`## 総合評価` ブロック内の Markdown** として書く。価格は記載時点の税込表示に合わせ、キャンペーンは条件・期限を販売ページに委ねる注記を付けてもよい（正本どおり）。

## サイト側の表示メモ（執筆時の参考）

- **引用（`>`）** … グレー背景・左アクセントで強調表示される（`ReviewMarkdown`）。
- **体験版・購入ボタン** … グラデーション＋ホバーで強調（一覧・詳細の `AffiliateButton`）。
- **総合評価の満点** … 本文で **`**★10／10**`**（スラッシュは `／` または `/`）と1つの太字にしたとき、**赤系の文字＋うっすら発光**で強調される（`ReviewMarkdown` の `strong`）。
- **`### 作品解説と感想`** … 見出し文言がこの**完全一致**のとき、他の `###` より**一段だけ文字を大きく**表示する（`## 作品像` は引き続き太字 `text-xl` の h2）。パート解説の `###` とは見た目を分けられる。表示位置は **星・価格・体験版ボタン行の直下**（本文続きブロックの先頭は `## 作品像`）。
- **`workImpressionAvatar`** … フロントマターに指定があるとき、**`## 作品感想`** の見出し行に**丸アイコン**が並ぶ（LINE のトプ画風。見出しの直右、本文とは別行に続く）。

## 文章の書き方（最強サンプルの原則）

- **抽象ラベルだけにしない**  
  - 悪い例：「テンポは一定ではありません」で終わる。  
  - 良い例：掛け合いではどう変わるか、乳首本番ではどう変わるか、**場面ごとに**書く。
- **短文の断定を並べない**（AIっぽさの典型）。意味はつなげ、**体感・比喩・呼吸**を入れる。
- **身体誘導・長尺パート**は「長い」単体だとネガティブに聞こえうる。**丁寧・時間をかけて・トランスに効く**など、意図が伝わる言い方にする。
- **事実の誤解を防ぐ**（例：「リング」＝実物の道具ではなく**指で輪を作る話**など）。必要なら一文で補足。
- **引用 `>`** は、台詞の「温度」を示すために使う。**パート解説では「引用1つ → その解説」を繰り返す**（上記「本文セクション構成」8）。引用だけを縦に並べない。
- **です・ます調**で統一しつつ、**一人称の感想**（`## 作品感想`）は自然な口語の範囲でよい。
- **メタで「聴いている側は」**を多用しない。主語を減らし、読者に寄せたり、情景に寄せたりする。

### 催眠技法・専門性の織り込み方（`## 作品像`・`## パート解説`）

**本節は「引用→解説」ルールと併用する。** 解説の段落こそ、**催眠・音声誘導の技法名や用語を入れる主の場所**（作品像は全体設計、パート解説は引用ごとの受け取り＋技法の補助線）。

催眠音声レビューは、**わかりやすさ**を軸にしつつ、**専門領域を扱っていること**が伝わるとよい。用語や技法名を**全面に押し出しすぎない**。**今の書き方（場面・体感・台詞の受け取り）を主**にし、技法は**そっと混ぜる**イメージで書く。正本は `kuchikou-saimin-count-trip-nouiki/index.md`（作品像・暗示・エッチ・解除の解説）。

- **狙い** … リスナーに「ちゃんと専門的な話をしている」「でも読んでわかる」と思ってもらう。威圧・見せつけ・用語の連打は避ける。
- **作品像** … トランス・逆カウント・合図・暗示の消去などは、**どのパートで何が起きるか**の説明のなかに自然に入れる。用語だけの列挙にしない。
- **パート解説** … **各引用の直後**に、その台詞の働き（防衛を下げる・数の意味を固定する・身体イメージを立ち上げる等）を書き、必要なら技法名を**その解説のなかで補助線**として置くと読みやすい。
- **用語を出すときの工夫**
  - **括弧は技法に** … `（）` での一言説明は、**催眠・音声誘導の「技法名」に付ける**のが主。**覚醒・後催眠・脱出・暗示（名詞としての通称）・深さの頂**のように、読めば意味が取れる語やパートの呼び方には、**わざわざ括弧を付けない**（読みやすさ優先）。**技法の例：** ペーシング、分割法、逆カウント、イメージ誘導、拮抗、アンカーリング、ラポール、トリガー、抑制、条件付け、段階的覚醒 など。技法を太字にしたときは、**括弧でひと言**（例：**ペーシング**（注意を声や音に乗せる誘導））を付けてよい。
  - **括弧でひと言**（例：いわゆる**分割法**（いったん覚醒させてから再導入）に近い役割）— 正本の暗示パート。**技法に対して**使う。
  - **一文で意味を足してから技法名**（「10から0へ…」のあとに逆カウントと呼べる、など）も有効。
  - **「技法名で言えば〜が、用語で飾るより〜」**の形で、台詞・体験を本筋に戻す— 正本のエッチパート（イメージ誘導・条件付けに近い反復）。技法名には必要なら括弧一言。
- **作品評価グラフ直下の三軸説明** … 軸の名前（トランス度・快楽度・満足度）と、**一文での言い換え**で足りることも多い。**技法名だけを並べて括弧だらけにしない**。
- **避ける** … 見出しや段落の先頭だけが専門用語になる並び、説明のない英語略語の羅列、読者テストのような難語、**覚醒などに不要な括弧**、**技法以外の語への括弧の乱発**。**教科書の目次**のような密度。
- **許容** … 正本どおり、**分割法**（いったん覚醒してから再導入する、など）のように**技法を太字＋括弧**で示す。

### 読みやすさのための改行（文体は変えない）

- **語句や口調はそのまま**に、**意味の区切り**で段落を分ける。1段落が画面幅いっぱいに続く長文は、**句点のあと**や**話題の切り替わり**で空行を入れる。
- **フロントマター**の `summary` / `itemDescription` は、複数行にしたいとき **`|` ブロック**で段落を分ける（補助参照の kyoku の `summary:` も可）。
- **見出し直後**の1行目が極端に長いときも、同じ要領で**空行**で呼吸を作る。
- 執筆後、スマホ幅のプレビューで**縦に詰まりすぎていないか**を確認する。
