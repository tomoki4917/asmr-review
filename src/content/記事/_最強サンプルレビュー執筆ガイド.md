# 最強サンプルレビュー執筆ガイド

## 正本（いつでもこれに合わせる）

### 第一正本（フォーマット・文体・三軸・作品感想・心拍の見せ方）

**`src/content/レビュー/futarigake-saimin-love-happy-orgasm/index.md`**（通称・**ラブハピ正本**）を、**収録／パート表の並べ方、総合評価（星・絶頂行・太字の `**グラフ評価内訳**`・三軸の書き方）、作品像・パート解説の言い回し、作品感想の温度と締め、Polar 心拍ブロックの構成**の**第一基準**にする。文体の細則は **`.cursor/rules/review-prose-voice.mdc`** も併用する（括弧は催眠誘導の手続きに限る、等）。

ラブハピ正本で示す運用の例：

- **`### 収録の長さ（パッケージ表記より）`**（短い形は `### 収録の長さ（パッケージ）` でも可）と **`### パートの長さ（目安）`** … **本編総尺は販売ページ（パッケージ）の表記を基本**とする。トラック別の**ネスト箇条書き**などは従来どおり。**文字起こし合算を本編の正として販売表記と併記する書き方は避ける**（パート表の分:秒は目安としてよい）。**「下記トラックの合算。実音声と数秒ずれる」**のような冗長注釈は付けない。ラブハピ正本の見出しに旧来の「文字起こしの合算目安」がある場合は、**新規・改稿時は上記のパッケージ表記優先に揃えてよい**。
- **`### 聴取時の身体反応（心拍）`** … 下記「心拍導入文の二系統」の **B. ラブハピ型**に従う（Polar・**快楽のタイミングとして波形を読む**導入、**末尾ノイズは ※ 脚注**、画像。本文に**長い bpm 読みを続けない**選択可）。ファイル名・alt は **`polar_h10_heart_rate_session.jpg`** / `![聴取セッション中の心拍数（Polar H10）](...)` に統一。
- **`## 総合評価`** … `**グラフ評価内訳**` の一行目印、三軸での**要点太字**、技法名は**説明のあとに全角括弧**（対象は**催眠誘導の技法・手続き**。状態・学習理論・生理俗語を括弧の「技法名」にしない）。
- **`## パート解説`** … **引用 → 解説**の反復は必須（unknown-hypno と同じ原則）。**括弧は誘導の手続き名に限る・同一技法の括弧は初出1回**などの細則は本文に**メタ注釈として書かない**（`review-prose-voice.mdc` に従う）。
- **`## 作品感想`** … 「今回はサークル…を聞かせていただきました。」から入り、**本作の型・誰に届くか**を短文で言い切る。**他サークル名・他作品・他 slug・前作比較は書かない**（本作の温度だけ）。
- **締め** … **「では、良き催眠ライフを👋」**（**では**と**良き**のあいだに読点）。
- **Polar がない作品** … 心拍見出しごと**省略**でよい（欠落ではない）。

新規レビューを書くときは、**構成・引用ルールは `unknown-hypno`・`_template.md` と整合**させつつ、**体裁・文体・三軸・心拍（B 型）・感想の型はラブハピ正本に合わせる**。自律神経の優位として波形を説明したい案件では、心拍導入の **A. polar10 固定文型**を選んでもよい（下記「心拍導入文の二系統」）。

**四区分（導入／暗示／エッチ／解除）の見本**として、短めの構成を参照したい場合は補助に `kuchikou-saimin-count-trip-nouiki/index.md` を使う。

執筆の流れの目安は次のとおり（いずれも本ファイルに記載あり）。

1. **構成・フロントマター** … 本文セクション構成・YAML。
2. **パート解説** … **引用1つ → その直後に解説**（本文セクション構成の 8）。解説文のなかで、台詞の働きとあわせて**催眠技法を混ぜる**（下記「催眠技法・専門性の織り込み方」）。**技法は解説段落に書くのが主**で、引用ブロックの中には書かない。**括弧 `（）` での一言説明は、主に「技法名」に付ける**（下記「括弧は技法に」）。覚醒・後催眠など、文脈で意味が取れる語には付けない。**注意事項トラック**を **`### 注意事項` で別立てしなくてよい**（定型のイヤホン・安全のみなら省略可。固有の導線は該当パートの解説に織り込む。詳細は `review-hypnosis-hemi-body.mdc`）。
3. **作品像** … 全体の設計の話を、同じく「催眠技法・専門性の織り込み方」に沿って書く（括弧ルールも同じ）。**論旨の組み立て・長所と短所の出し方**は**ラブハピ正本**のトーンに寄せる。あわせて下記「**台本の身体の動き・心拍**」に従い、**台本が求める身体の動き**を必ず書く（**寝て聴く前提**や**大きな体操をしないこと**など、読み手のデフォルトとの**無謂な繰り返し・対比は書かない**。非デフォルトの動きだけ明示。詳細は同節）。
4. **「ヘミシンク」という語（該当時のみ）** … 台本に**語が出てくる**作品では、`## 作品概要` に**専用見出しを立てない**。**`## パート解説`** で、**該当する引用の直後の解説**に**一文**で意味を足す（左右の耳にずれた音で脳がリズムを感じる系の音の通称、など）。**語が出てこない作品では書かない**。
5. **聴取時の身体反応（心拍・該当時）** … 解析フォルダ等に **心拍セッション画像**が渡されている場合は、**必ず** **`### 聴取時の身体反応（心拍）`** を `## 作品概要` に載せる。**新規は原則ラブハピ正本どおりの B 型**（下記「心拍導入文の二系統」）。自律神経の優位説明が主目的なら **A 型（warui／polar10 固定文）**でもよい。**画像がない作品では省略**（Polar がないだけのレビューも多い）。
6. **生体ログの運用** … 心拍を載けない作品では本項は不要。載ける場合の補助参照：`warui-inma-kanashiki-koufuku-nadenade-hagu`（数値帯の例）、`tenshi-akuma-souhan-saimin`（数字少なめの例）。**波形読みの段落分け・太字・パート対応**は **unknown-hypno** を参照。

分析データ・尺・スタッフ名・購入リンクなどの**事実データは、筆者が別ファイルでまとめて渡す前提**とする。AIはそのデータを本文の適切な位置に埋め込み、**本ガイド・ラブハピ正本の体裁・文体・unknown-hypno の構成・引用ルール**に従って執筆する。

## フロントマター（YAML）

**unknown-hypno** および既存レビューと同様に、次を揃える。

| 項目 | 役割 |
|------|------|
| `slug` | URL・フォルダ名と一致する一意の ID |
| `title` | ページタイトル（作品名＋必要なら「レビュー」等） |
| `summary` | 一覧・OGP 用の短い紹介。**解析方法・タイムスタンプ・セグメント境界などのメタは書かない**（読者向けに作品の魅力・型を一文〜数文で。例：王道派・本格誘導・何を狙うか）。`itemDescription` も同様。正本（unknown-hypno）は **複数段落**（`summary:` の次行に `|` を置く書き方）の例。1 段落のみでも可。 |
| `tags` | 催眠音声・属性タグなど（サイトの絞り込みに使う）。**人外**（妖怪・魔物・スライム等の非人キャラが主題のとき）は必ず **`人外`** を含める。 |
| `ratingValue` / `ratingBest` | 星評価（通常は 10 点満点換算） |
| `itemName` / `itemDescription` | 構造化データ用（未入力時は summary 等にフォールバックしうる） |
| `authorName` | 著者表示 |
| `publishedAt` | `YYYY-MM-DD` |
| `coverImage` | 主ビジュアル URL または `/content/reviews/<slug>/...`（推奨・ASCII パス） |
| `coverAffiliateHref` | 任意。ジャケット画像クリック用 |
| `affiliateLinks` | 体験版・購入ボタン等（vendor / href / label） |
| `dlsiteProductId` | **DLsite 作品のときは付与推奨**（`RJ` + 数字）。トップ一覧カードの **税込・セールバッジ・取り消し線付き定価** は、リポジトリ直下 **`data/products.json`** の **`id` が一致する行**を参照する（本文の価格欄とは別系統。**一覧の見た目は JSON が正**）。**今後の新規レビューでも毎回**、下記「新規レビューでの価格反映」と同じ手順に従う。一覧に価格を出さない場合は環境変数 `NEXT_PUBLIC_SHOW_DL_PRODUCT_PRICES=false`。 |
| `workImpressionAvatar` | 任意。**`## 作品感想`** 見出しの**直右**に、LINE のトプ画のような**丸アイコン**（ムキネコ等）を出す。`coverImage` と同じく **`/content/reviews/<slug>/ファイル名`**（ASCII パス）。**未指定時は**サイト側の既定画像（コード内の正本パス）が使われる。作品ごとに差し替えるときだけ指定する。PNG をレビューフォルダ直下に置き、`npm run sync:content-assets` で配信。本文に `![](同じURL)` を**書かない**（サイト側の `ReviewMarkdown` が見出し行に描画するため重複になる）。 |

**一覧カードの表示（執筆時のイメージ合わせ）** … トップのレビューカードは次の並びになる（実装は `ReviewCard`・`StarRating`・`ReviewDlsiteListPrice`）。

- **投稿** … `publishedAt`（`YYYY-MM-DD`）
- **タイトル** … `title`（一覧用に1行に潰した表示）
- **星 + 分数** … 5 段階の星と **`ratingValue`／`ratingBest` の数値**（満点時のみ赤強調、それ以外はスカイ系）
- **価格** … `dlsiteProductId` があり `products.json` に行があり `current_price` が正のとき、**セール中は赤 `n%OFF`・黄の現在価格・灰の取り消し定価**（税込）
- **タグ** … `tags`（スカイ系のピル）

**本文の `## 総合評価` には、価格・クーポン・体験版の有無を箇条書きしない**（トップ一覧の税込・セール・詳細の体験版ボタンで代替できるため）。価格の正本はリポジトリ直下 **`data/products.json`**（フロントマター `dlsiteProductId` と紐づく行）。執筆・改稿時は **`npm run update-prices`** で同期する運用は従来どおり。

**新規レビューでの価格反映（今後の記事も毎回）**

1. フロントマターに **`dlsiteProductId: RJ……`** を書く。
2. **`data/products.json`** の配列に **1 件追加**する。最低限 **`id`**（`dlsiteProductId` と同じ）と **`url`**（`https://www.dlsite.com/maniax/work/=/product_id/RJ…….html`）があればよい（他フィールドはスクリプトが上書きする）。
3. リポジトリルートで **`npm run update-prices`** を実行する（DLsite から税込・セール率・期限などを取得し、該当行を埋める。全件に数分かかる）。
4. **`products.json` の変更をコミット**する。手動実行を省略する場合は、週次の CI 更新が入るまで一覧が遅れることがある。

セール終了後に JSON だけセール中のまま残るときは、`npm run update-prices:stale`（`--stale-sale-ended` と同じ）で期限切れ行だけ再取得できる。

画像・グラフは **レビューフォルダ直下**（`src/content/レビュー/<slug>/`）に置く。本文・HTML で参照する URL は **`/content/reviews/<slug>/ファイル名`** に統一する（英数字パスのみ）。`npm run dev` / `npm run build` の前に走る `sync-content-assets` が `src` 側の非 Markdown 資産を `public/content/レビュー/` にコピーし、**同じ内容を `public/content/reviews/` にもミラー**する。`/content/レビュー/...` のように **日本語フォルダ名を URL に含めると本番で画像が壊れる**ことがあるため、**必ず `reviews` 側を参照**すること。

## 本文セクション構成（この順で揃える）

**unknown-hypno** に合わせた標準構成。**Markdown ファイル上の並び**は次のとおり。

サイトでは `splitBodyAtFinalRating` により、**`## 総合評価` 見出しの直後から、次の `## `（h2）直前まで**が「総合評価」欄用の `rating`、**その次の `## ` から下**が `rest` になる。

さらに `splitRatingAtWorkIntroLabel` により、`rating` 内の **`### 作品解説と感想` 行の直前**で分割される。**星・価格・注記・区切り線まで**が「総合評価」ブロックの**左列**と、横の**体験版ボタン**（`affiliateLinks` があるとき）が**同じ段**に並ぶ。`### 作品解説と感想` 見出しと、その直下に書く短文（あれば）は**その下の段**に表示され、**スマホでも体験版ボタンが「作品解説と感想」ラベルの下に落ちない**。`## 作品像` は引き続き `rest` の先頭。

1. **`## 作品名`** … 太字でフルタイトル1行。直後に `---`。
2. **`## 作品概要`**
   - `### 基本情報` … サークル・種類・CV・シナリオ・イラスト等（渡されたデータを箇条書き）
   - `### 収録の長さ（パッケージ表記より）` … 正本の見出し。**短く揃えたい場合**は `### 収録の長さ（パッケージ）` でも可（補助参照の kyoku はこちらの短い形）。本編・派生トラックの尺を箇条書き。
   - `### パートの長さ（目安）` … 次の**いずれか**に揃える（混在可）。
     - **四区分型（kuchikou 補助参照）** … 先頭に **導入 → 暗示 → エッチ → 解除** などへの分け方を一文で示し、**`- **パート名** — 約 0:00–4:43（短い説明）`** をフラットに並べる。境界はトラック名・台詞の転換・無音の変化などから決め、**見出しに「解析データによる」などのメタは付けない**（目安で十分）。
     - **トラック番号型（正本・unknown-hypno）** … `- **01** 注意事項 … 約 **1:32**` のように、**番号・タイトル・時間（分:秒）**を1行ずつ。区切り方の前提を一文で足すのは任意。**文字起こしと実音声のズレに関する注釈は書かない**（ラブハピ正本の方針どおり）。
     - **ネスト型（futarigake 補助参照）** … 本編合計の下にトラックごとをインデントした箇条書き。
   - 必要なら1行メモ（例：絶頂シーン数）… 見出しが不要ならプレーンテキスト1行でも可
   - **`### 聴取時の身体反応（心拍）`（任意）** … Polar H10 等で心拍ログを載せるとき。**新規は原則ラブハピ正本の B 型**（下記「心拍導入文の二系統」）。自律神経説明が主なら **A 型（warui／polar10 固定文＋波形読み）**でもよい。配置は **`### パートの長さ（目安）` の直後、`### 作品評価グラフ` の直前**を推奨。`summary` に数値や測定手順のメタを書かないルールは維持する。
   - **`### 作品評価グラフ`** … レーダー等の画像1枚。`![作品評価グラフ（トランス度・快楽度・満足度）](/content/reviews/<slug>/review_triangle.png)` のように書く（見出しに「アイアン・トライアングル」等の別名は**不要**でよい）。**グラフの形・数値は、`## 総合評価` 内の三軸説明（トランス度・快楽度・満足度の点数）と必ず一致**させる。`src/content/レビュー/<slug>/_分析データ.txt` に **`トランス度` / `快楽度` / `満足度`（いずれか1行）** と **`作品名:`** を書き、`py -3 scripts/generate_review_triangle.py <slug>` で `review_triangle.png` を出力 → `npm run sync:content-assets` で反映。定義は `docs/レビュー三軸評価定義.md` に従う。三軸の1行説明はラブハピ正本のように **満足度＝興奮のあとの収束と安心感** でも、他レビューで使っている **安らぎと体験の収束** でもよい（サイト統一したいときは揃える）。**満足度**は**解除・余韻に加え、尺（再生時間）に見合う体験として約束が回収できているか**も含めてよい（**長尺を「短い方がよい」という別物の物差しで一蹴しない**。長尺ならではの深化・余韻が揃う場合は高く評価してよい。詳細は同ドキュメント「尺との見合い」および「尺の呼び方（レビュー室・本文用の目安）」）。
   - ブロックの終わりに `---`

## 文章の書き方（最強サンプルの原則）

- **抽象ラベルだけにしない**  
  - 悪い例：「テンポは一定ではありません」で終わる。  
  - 良い例：掛け合いではどう変わるか、乳首本番ではどう変わるか、**場面ごとに**書く。
- **短文の断定を並べない**（AIっぽさの典型）。意味はつなげ、**体感・比喩・呼吸**を入れる。
- **身体誘導・長尺パート**は「長い」単体だとネガティブに聞こえうる。**丁寧・時間をかけて・トランスに効く**など、意図が伝わる言い方にする。
- **事実の誤解を防ぐ**（例：「リング」＝実物の道具ではなく**指で輪を作る話**など）。必要なら一文で補足。
- **引用 `>`** は、台詞の「温度」を示すために使う。**パート解説では「引用1つ → その解説」を繰り返す**（上記「本文セクション構成」8）。引用だけを縦に並べない。
- **です・ます調**で統一しつつ、**一人称の感想**（`## 作品感想`）は自然な口語の範囲でよい。
- **メタで「聴いている側は」**を多用しない。主語を減らし、読者に寄せたり、情景に寄せたりする。

### 催眠技法・専門性の織り込み方（`## 作品像`・`## パート解説`）

**本節は「引用→解説」ルールと併用する。** 解説の段落こそ、**催眠・音声誘導の技法名や用語を入れる主の場所**（作品像は全体設計、パート解説は引用ごとの受け取り＋技法の補助線）。

催眠音声レビューは、**わかりやすさ**を軸にしつつ、**専門領域を扱っていること**が伝わるとよい。用語や技法名を**全面に押し出しすぎない**。**今の書き方（場面・体感・台詞の受け取り）を主**にし、技法は**そっと混ぜる**イメージで書く。長尺・パート解説の**引用の厚み・密度**の見本は **`unknown-hypno-daijobu-koe-ni-yudanete/index.md`**。**作品像の読みやすさ・総合評価・作品感想の口調**は**ラブハピ正本**を参照。四区分の短い構成の見本は `kuchikou-saimin-count-trip-nouiki/index.md`（作品像・暗示・エッチ・解除の解説）。

- **狙い** … リスナーに「ちゃんと専門的な話をしている」「でも読んでわかる」と思ってもらう。威圧・見せつけ・用語の連打は避ける。
- **作品像** … トランス・逆カウント・合図・暗示の消去などは、**どのパートで何が起きるか**の説明のなかに自然に入れる。用語だけの列挙にしない。
- **パート解説** … **各引用の直後**に、その台詞の働き（防衛を下げる・数の意味を固定する・身体イメージを立ち上げる等）を書き、必要なら技法名を**その解説のなかで補助線**として置くと読みやすい。
- **用語を出すときの工夫**
  - **括弧は技法に** … `（）` での一言説明は、**催眠・音声誘導の「技法名」に付ける**のが主。**覚醒・後催眠・脱出・暗示（名詞としての通称）・深さの頂**のように、読めば意味が取れる語やパートの呼び方には、**わざわざ括弧を付けない**（読みやすさ優先）。**技法の例：** ペーシング、分割法、逆カウント、イメージ誘導、拮抗、アンカーリング、ラポール、トリガー、抑制、条件付け、段階的覚醒 など。技法を太字にしたときは、**括弧でひと言**（例：**ペーシング**（注意を声や音に乗せる誘導））を付けてよい。
  - **括弧でひと言**（例：いわゆる**分割法**（いったん覚醒させてから再導入）に近い役割）— kuchikou の暗示パート等の例。**技法に対して**使う。
  - **一文で意味を足してから技法名**（「10から0へ…」のあとに逆カウントと呼べる、など）も有効。
  - **「技法名で言えば〜が、用語で飾るより〜」**の形で、台詞・体験を本筋に戻す— kuchikou のエッチパート等（イメージ誘導・条件付けに近い反復）。技法名には必要なら括弧一言。
- **作品評価グラフ直下の三軸説明** … 軸の名前（トランス度・快楽度・満足度）と、**一文での言い換え**で足りることも多い。**技法名だけを並べて括弧だらけにしない**。**同一の技法名を括弧付きで繰り返さない**（1記事につきその用語の括弧は初出の1回まで。三軸とパート解説で二重に付けない）。中尺・長尺では**満足度**に**尺に見合う密度・着地**を書いてよい（**長いから減点**ではない。`docs/レビュー三軸評価定義.md`「尺との見合い」）。**「長尺」という語の目安**は同ドキュメント「尺の呼び方（レビュー室・本文用の目安）」。
- **避ける** … 見出しや段落の先頭だけが専門用語になる並び、説明のない英語略語の羅列、読者テストのような難語、**覚醒などに不要な括弧**、**技法以外の語への括弧の乱発**。**教科書の目次**のような密度。
- **許容** … kuchikou の例のように、**分割法**（いったん覚醒してから再導入する、など）のように**技法を太字＋括弧**で示す。

### 台本の身体の動き・心拍・「ヘミシンク」という語（催眠レビューで必ず触れる）

読者が「何をする音声か」を誤解しないよう、次を**ルール化**する。

- **「ヘミシンク」という語** … 台本・トラックに**その語が出てくる**作品だけ、`## パート解説` の**該当引用の解説**の**先頭に一文**で意味を足す（左右の耳にわずかにずれた音をかけ、脳がその差をリズムとして感じ取るタイプの音を指す通称、など）。**`## 作品概要` に `### ヘミシンクとは` のような専用見出しは置かない**。語が出てこない作品では、説明も不要。
- **台本が求める身体の動き**は、**必ず** `## 作品像` または `## 作品概要` のどちらかで、聴き手に求められる**動きの範囲**を一文以上で書く。**寝て聴く・ベッドや布団**、**大きな体操をしない・受け身で聴くだけ**など、催眠音声では読み手の前提とみなし、**わざわざ繰り返したり、当たり前の否定や対比に使わない**。台本が**立位の体操・片付け・実演ワークアウト**や**座位・目を開ける等の特殊指示**、**R18 パートの局所の具体的指示**など**通常と違う動き**を求めるときは、その内容を必ず書く。デフォルトのみの作品では、**脱力・呼吸・想像に任せる範囲**など、台本が実際に言っている動きで足りる。じっと聴くか身体を動かすかの**タイプ対比**は、**その差が台本の特徴として意味を持つとき**に限って書く。
- **心拍ログ（身体活動の記録）** … 筆者が解析フォルダ等で **Polar H10 等のセッション波形画像**（例：`身体活動.jpg`）を渡した場合は、**聴取時の身体反応として必ず本文に載せる**。ブロックの型は下記 **「心拍導入文の二系統」** と **「聴取時の身体反応（心拍）— 標準フォーマット」** に従う（**新規は原則 B**：`futarigake-saimin-love-happy-orgasm`。自律神経の優位説明が主なら **A**：polar10 固定文→画像→波形読み、`warui-inma-kanashiki-koufuku-nadenade-hagu`）。**画像ファイルはレビューフォルダ直下の `polar_h10_heart_rate_session.jpg` に統一**する（解析側が別名でも、公開用にコピーしてから参照）。配置は **`### パートの長さ（目安）` の直後、`### 作品評価グラフ` の直前**。**心拍画像がない作品では本項ごと省略**。

補足：**「身体活動」**という言い方で渡されるデータが、上記の**心拍グラフ**であることが多い。画像があるときは文章だけで「身体活動」と済ませず、**必ず `### 聴取時の身体反応（心拍）` ブロック**（**A または B**）を入れる。

### 読みやすさのための改行（文体は変えない）

- **語句や口調はそのまま**に、**意味の区切り**で段落を分ける。1段落が画面幅いっぱいに続く長文は、**句点のあと**や**話題の切り替わり**で空行を入れる。
- **フロントマター**の `summary` / `itemDescription` は、複数行にしたいとき **`|` ブロック**で段落を分ける（補助参照の kyoku の `summary:` も可）。
- **見出し直後**の1行目が極端に長いときも、同じ要領で**空行**で呼吸を作る。
- 執筆後、スマホ幅のプレビューで**縦に詰まりすぎていないか**を確認する。

## 聴取時の身体反応（心拍）— 標準フォーマット（波形読みの書き方）

Polar H10 等のセッション波形を載せるレビューでは、`## 作品概要` のなかに次の **ひとかたまり** を置く。**導入文の型（A / B）**は**上の「心拍導入文の二系統」**に従う。波形読みの実例は **`unknown-hypno-daijobu-koe-ni-yudanete`**（段落分け・太字・パート対応）、**`warui-inma-kanashiki-koufuku-nadenade-hagu`**（数値帯）、**`tenshi-akuma-souhan-saimin`**（数字少なめ）、**`futarigake-saimin-love-happy-orgasm`**（**B 型・読み省略**）の `### 聴取時の身体反応（心拍）` 節。

### 並び順（導入の型に応じて）

1. **見出し（h3）** … `### 聴取時の身体反応（心拍）`
2. **導入文** … **A 型**：下記「生体ログ・心拍グラフの固定文」の **1文を一字一句そのまま**（画像の直前。見出しと固定文のあいだに別文を入れない）。**B 型**：「心拍導入文の二系統」の **B**（Polar・快楽としての読み方・任意 `※`）。**B 型では導入を複数文にしてよい**。
3. **画像（1枚）** … レビューフォルダ直下を推奨。パスは **`/content/reviews/<slug>/…`** の ASCII のみ。ファイル名は **`polar_h10_heart_rate_session.jpg`** に統一する（解析フォルダ側が別名でも、公開用にコピーしてこの名前に揃える）。
4. **Markdown 行** … 次の形式を用いる（alt 文言もこのまま）。

   `![聴取セッション中の心拍数（Polar H10）](/content/reviews/<slug>/polar_h10_heart_rate_session.jpg)`

5. **波形の読み（本文段落）** … **B 型では省略可**。**A 型、または B で読みを載せる場合**は画像の**直後**に続ける。**時間軸**で区切る（例：**前半**／**中盤から後半**／**終盤**、または作品のパート境界に合わせた語）。**読みの主役は「線の位置・上下の様子」と主観の身体感覚**とする。bpm やピーク数値を並べるより、次のような**わかりやすい言い換え**を優先してよい。
   - **文体** … 波形の読み（測定条件・区間ごとの説明を含む）は**です・ます調**で統一する。補助参照の `tenshi-akuma-souhan-saimin` は**だ調の例**も含むが、新規・改稿では本項に従う。
   - **数値の表記** … 心拍の帯・ピークなど**数値はアラビア数字**（例：**70〜80 bpm**）。**漢数字（七十台など）は使わない**（読みにくいため）。
   - **区間ごとの書き方（推奨）** … 長尺では、**区間ごとに**（1）どちらの自律神経が優位になりやすいか、（2）その区間で起きている**聴取上の現象**（誘導・台詞の切替・本番など）、（3）それに合わせて**線がどう動くか**、の順で短く書くと読みやすい。太字で小見出しを付けて段落を分けてもよい（例：`sukisuki-surikomi-chudoku-onanie-saimin`）。
   - **低めの帯にいるとき** … 例：「いまの数字が **70〜80 bpm** で低い＝身体は休めに寄っている」「このくらいだとトランスに入りやすい」など、**一文で意味を渡す**。
   - **線が持ち上がったり細かく跳ねるとき** … 安静時より上のレンジ、胸がざわつく、呼吸が浅い、など**体感語**で十分。必要なら帯やピークを **おおよそ一つだけ** 数値で補足してもよい（細かい bpm の列挙は避ける）。
   - **自律神経の語** … **副交感神経**・**交感神経**を出す場合は軽く（「休む側が優位になりやすい」など）。**交感神経**に長い括弧説明（例：身体を起こす側の自律神経）を**毎回付けない**。通じるなら用語だけ、または言い換えのみでよい。
   - **終盤** … 下がり切って心地よい、息が深く入る、など主観で十分。**クールダウン**（興奮のあとに線が落ち着く）を指す語を使ってもよいが、教科書的な断定の羅列は不要。
   - **測定上のノイズ** … 寝落ち直前に無理に身体を起こした、機器のズレ、など**線の最後の跳ね**の理由が分かるときは、正直に一文添えてよい（読者がグラフを信頼しやすくなる）。

段落は **warui 補助参照のように一続きの長め**でも、時間帯ごとに **太字小見出し**（`**グラフ左・誘導が続く区間**` など）で分ける形でも、**太字なしで「前半は…」「中盤から…」と文中で切る**形でもよい。**unknown-hypno** は複数段落＋太字で区間を示す例。数式や機器仕様の説明は不要。**`summary` には心拍数・測定手順・センサ型番の羅列を載せない**（概要欄は読者向けのまま）。
