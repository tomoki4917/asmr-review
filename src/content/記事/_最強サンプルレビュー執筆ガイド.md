# 最強サンプルレビュー執筆ガイド

## 正本（いつでもこれに合わせる）

**参照ファイル（フォーマット・文章の両方の正）：**

`src/content/レビュー/kyoku-mugen-zekkyou-count-chikuni/index.md`

新規レビューを書くときは、**まずこのファイルを開き、見出しの並び・段落の密度・引用の入れ方をそのまま真似する**。分析データ・尺・スタッフ名・購入リンクなどの**事実データは、筆者が別ファイルでまとめて渡す前提**とする。AIはそのデータを本文の適切な位置に埋め込み、このガイドと正本の**文体ルール**に従って執筆する。

## フロントマター（YAML）

正本どおり、次を揃える。

| 項目 | 役割 |
|------|------|
| `slug` | URL・フォルダ名と一致する一意の ID |
| `title` | ページタイトル（作品名＋必要なら「レビュー」等） |
| `summary` | 一覧・OGP 用の短い紹介 |
| `tags` | 催眠音声・属性タグなど（サイトの絞り込みに使う） |
| `ratingValue` / `ratingBest` | 星評価（通常は 10 点満点換算） |
| `itemName` / `itemDescription` | 構造化データ用（未入力時は summary 等にフォールバックしうる） |
| `authorName` | 著者表示 |
| `publishedAt` | `YYYY-MM-DD` |
| `coverImage` | 主ビジュアル URL または `/content/reviews/<slug>/...`（推奨・ASCII パス） |
| `coverAffiliateHref` | 任意。ジャケット画像クリック用 |
| `affiliateLinks` | 体験版・購入ボタン等（vendor / href / label） |

画像・グラフは **レビューフォルダ直下**（`src/content/レビュー/<slug>/`）に置く。本文・HTML で参照する URL は **`/content/reviews/<slug>/ファイル名`** に統一する（英数字パスのみ）。`npm run dev` / `npm run build` の前に走る `sync-content-assets` が `src` 側の非 Markdown 資産を `public/content/レビュー/` にコピーし、**同じ内容を `public/content/reviews/` にもミラー**する。`/content/レビュー/...` のように **日本語フォルダ名を URL に含めると本番で画像が壊れる**ことがあるため、**必ず `reviews` 側を参照**すること。

## 本文セクション構成（この順で揃える）

正本（kyoku）に合わせた標準構成。

1. **`## 作品名`** … 太字でフルタイトル1行。直後に `---`。
2. **`## 作品概要`**
   - `### 基本情報` … サークル・種類・CV・シナリオ・イラスト等（渡されたデータを箇条書き）
   - `### 収録の長さ（パッケージ）` … 本編・派生トラックの尺
   - `### パートの長さ（目安）` … トラック単位の目安
   - 必要なら1行メモ（例：絶頂シーン数）… 見出しが不要なら正本のようにプレーンテキスト1行でも可
   - **`### 作品評価グラフ`** … レーダー等の画像1枚。`![作品評価グラフ（トランス度・快楽度・ストーリー性）](/content/reviews/<slug>/ファイル名.png)` のように書く（見出しに「アイアン・トライアングル」等の別名は**不要**でよい）
   - ブロックの終わりに `---`
3. **`## 作品像`** … **読者を物語に引き込む総論**。テンポの変化は「一定ではない」だけにせず、**どのパートでどう変わるか**を具体的に書く。
4. **`## パート解説`** … `### パート名（番号）── キャッチ` で小見出し。各パートで**説明 → 引用（`>`）→ 身体・感情の反応**のリズムを作る。
5. **`## 総評`**
   - `### 作品感想` … 筆者の一人称・体験ベースでよい（正本のトーン参照）
   - ※グラフは**作品概要**側に置く（総評の下には置かない）
6. **`## どんな人におすすめか`** … 箇条書き＋**合わない人**を1行で明示
7. **`## 総合評価`** … 見出し直後に **`**★n／10**`**（**`★10／10` はサイト側で赤系に強調表示**される）。続けて任意で **価格・クーポン・体験版**などを箇条書きし、価格・キャンペーンの変動に関する注記を付けてもよい（正本参照）。横並びの **「作品ページはこちら」**は `affiliateLinks` があるとき自動表示。

セクション間は `---` で区切る（正本に合わせる）。

### フロントマターの `affiliateLinks` と「総合評価」

- 本文に **`## 総合評価`** があり、かつ **`affiliateLinks` に1件以上**あるとき、レビュー詳細ページでは **「総合評価」見出しの横に「作品ページはこちら」ボタン**（先頭リンクのラベルをこの文言に差し替え）が並ぶ。
- その場合、ページ下部の別枠「作品のページへ」は**出さない**（重複防止）。
- `## 総合評価` を消すと分割されず、従来どおり下部に「作品のページへ」だけ出る。
- 星の行以降も **`## 総合評価` ブロック内の Markdown** として書く。価格は記載時点の税込表示に合わせ、キャンペーンは条件・期限を販売ページに委ねる注記を付ける（正本どおり）。

## サイト側の表示メモ（執筆時の参考）

- **引用（`>`）** … グレー背景・左アクセントで強調表示される（`ReviewMarkdown`）。
- **体験版・購入ボタン** … グラデーション＋ホバーで強調（一覧・詳細の `AffiliateButton`）。
- **総合評価の満点** … 本文で **`**★10／10**`**（スラッシュは `／` または `/`）と1つの太字にしたとき、**赤系の文字＋うっすら発光**で強調される（`ReviewMarkdown` の `strong`）。
- 上記は Markdown を変えずにスタイルが当たるため、**本文は内容のみ**意識すればよい。

## 文章の書き方（最強サンプルの原則）

- **抽象ラベルだけにしない**  
  - 悪い例：「テンポは一定ではありません」で終わる。  
  - 良い例：掛け合いではどう変わるか、乳首本番ではどう変わるか、**場面ごとに**書く。
- **短文の断定を並べない**（AIっぽさの典型）。意味はつなげ、**体感・比喩・呼吸**を入れる。
- **身体誘導・長尺パート**は「長い」単体だとネガティブに聞こえうる。**丁寧・時間をかけて・トランスに効く**など、意図が伝わる言い方にする。
- **事実の誤解を防ぐ**（例：「リング」＝実物の道具ではなく**指で輪を作る話**など）。必要なら一文で補足。
- **引用 `>`** は、台詞の「温度」を示すために使う。前後に筆者の受け取りを必ず書く。
- **です・ます調**で統一しつつ、**一人称の感想**（総評の作品感想）は自然な口語の範囲でよい。
- **メタで「聴いている側は」**を多用しない。主語を減らし、読者に寄せたり、情景に寄せたりする。

## AIっぽさを減らすチェックリスト

- [ ] 「〜です。」が同じ長さで5回以上続いていないか  
- [ ] テンポ・雰囲気・構造を、**どこでどう変わるか**一言以上あるか

- [ ] ネガティブに聞こえる単語（長い・遅い等）は、文脈でプラスに転じているか  
- [ ] 作品固有の造語・パート番号・シーン名が、データと一致しているか
