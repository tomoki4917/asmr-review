# 同人音声（シチュボイス）執筆ガイド（仮）

## 新方針（2026-05 追記・仮運用）

以下は、同人音声レビューを「催眠適性評価」ではなく、**音響作品としての設計評価**へ寄せるための仮ルール。正本へ統合する前提で本ファイルに先行記載する。

**フォーマット参照方針（重要）**  
記事の**見出し構造・段組・配置ルール**は、`docs/真催眠音声執筆ガイド.md` のうち**同人レビューへ無理なく転用できる項目だけ**を参照する。  
一方、催眠固有の規定（誘導手続きの評価語、催眠特有の評価軸・用語、催眠前提の断定）は同人レビューへ持ち込まない。

### 執筆前：販売ページ（DLsite）情報の取得（同人・必須・2026-05-20）

**`index.md` 執筆・改稿の前に**、フロントマターの **`dlsiteProductId`**（例：`RJ01531480`）で **DLsite 作品ページ**を参照し、**解析データと突き合わせる**。同人は催眠と違い、**シチュ・キャラ・トラック表**が販売側に明示されているため、**WhisperX／librosa だけから推測で書かない**。

**取得して正本に置く項目**

| 項目 | 用途 | 記事での置き場 |
|------|------|----------------|
| **Character**（名前・役割・関係・口調） | リアリティ・おすすめシチュ | `### 基本情報` の **キャラクター**行、`tags`、パート解説の舞台 |
| **Concept & Story**（売り文句の因果） | ねじれフック・コンセプト達成度 | `summary`／`itemDescription`（★分岐） |
| **TrackList**（公式トラック名・尺・舞台・内容タグ） | パート表・必然性・テンポ | `### パートの長さ` の**表**、パート見出し・`内容:` |
| **総再生時間・本編／特別パートの区別** | 購入判断・クイック収録 | 合計行（本編）／クイック `recording`（内訳） |
| **収録機材・ファイル形式** | カタログ事実 | `### 基本情報` の **収録:** のみ（KU100 前提論は §「収録マイク名」） |
| **購入特典・ループ音声** | 執筆者メモ | `_分析データ.json` の `notes` または執筆メモ。**読者向け本文・グラフ・summary では列挙しない**（採点外） |

2. **解析フォルダ** … トラックファイル名・`info.txt` の RJ と **DLsite トラック表が1:1** か確認。尺は**販売表記を正**とし、計測差は `_分析データ.json` の `notes` に留める。  
3. **計測パイプライン**（下記）… `spatial_spectral`・`derived_metrics` で**音響・定位・声色の変化**を補強。  
4. **DLsite ユーザーレビュー傾向** … 上記パイプライン **4**（`fetch-dlsite-user-reviews.mjs`・**文章のみ**）。  
5. **`index.md`** … サイトの**舞台・キャラ・公式トラック名**を先に載せ、**おすすめ・グラフ・パート解説**は計測・台詞・**購入者レビュー本文の傾向（言い換え）**で裏取りする。

**見本** … `dakimakura-kanojo-pretty-holic-yurukawa-kouhai`（戸丸更紗／生徒会書記、7トラック表、本編6＋【安眠用】）。

### 解析フォルダと計測パイプライン（2026-05 追記・必須）

ユーザーが毎回渡す**解析フォルダ**（`.mp3`・`.srt`・`*_waveform.csv`・文字起こし `json`／`txt` 等）を受け取ったら、**`index.md` 執筆の前に** `docs/真催眠音声執筆ガイド.md` の **§1（補・解析パイプライン）** と同じ順で実行する。

1. **`analyze_mp3_immersive_metrics.py`** … 定位（左右 RMS 差）・スペクトル重心・4 kHz 以上のエネルギー比（**質感・息・歯擦音寄りの目安**。囁きの機械断定ではない）を `spatial_spectral.auto.json` に書く。  
2. **`import-review-analysis.py`** … 音声以外を `analysis/` へ。  
3. **`analyze_review_auto.py`** … `derived_metrics.json` 等。**1 のあと**なら `immersive_audio_mp3` が `derived_metrics` に取り込まれる。  
4. **DLsite ユーザーレビュー傾向** … `node scripts/fetch-dlsite-user-reviews.mjs RJ… <slug> --update-notes`（**計測のあと・`index.md` の前**）。**`review_text`（＋ title）のみ**を読み、繰り返し言及を `dlsite_review_trends.auto.json` に記録。**おすすめ・本文へ言い換えて薄く反映**（下記「DLsite ユーザーレビュー」）。**星・`rate_num` は参照しない**。

**同人レビューでの位置づけ:** 定位・ミックスの揺れ・「耳元の質感」は**説得の主戦場**になりやすい。**総合の星・五軸に当てはめる材料**として用い、数値を星に機械換算しない。本文・`summary` へ**スクリプト名・JSON 素片・閾値の断片**を直貼りしない（読者向けの言葉へ翻訳。`_分析データ.json` の `notes` は執筆者向け）。

### DLsite ユーザーレビュー（同人・執筆前・2026-05-20）

**取得元:** `https://www.dlsite.com/maniax/api/review`（`product_id`・`limit`・`page`・`order=regist_d`・`mix_pickup=1`）。作品ページの `<product-review-list>` は Vue 描画のため、**静的 HTML だけでは本文が取れない**。**API または `fetch-dlsite-user-reviews.mjs` を使う**。

**参照するのは文章だけ** … `review_title` と `review_text` のみ。**`rate_num`・星・いいね数は執筆に使わない**。

**手順**

1. `node scripts/fetch-dlsite-user-reviews.mjs RJ… <slug> --update-notes`  
2. **`analysis/dlsite_reviews.auto.json`**（原文・執筆者のみ）と **`analysis/dlsite_review_trends.auto.json`**（繰り返しテーマ・おすすめ／合わないの反映ヒント）を確認。  
3. 複数レビューで**繰り返し出る語・体験**（例：イチャラブ、キス多め、添い寝で眠気、連戦の密度）を読み取り、**自分の聴取・計測と矛盾しない範囲**で反映する。  
4. **反映してよい場所** … **`summary`・`itemDescription`**・**`おすすめしたい方`（3）**・**`合わない可能性がある方`（2）**・**グラフ評価内訳**・**パート解説**・**総評**。聴取・計測・DLsite販売情報と**矛盾しない範囲**で、記事全体に**言い換えて**織り込む（整合性優先）。**採点（`ratingValue`・五軸）の主根拠は音声**（`review-audio-work-only-scoring.mdc`）。  
5. **禁止** … 購入者の**原文引用・コピペ**・**「DLsiteのレビューでも〜」**・レビュアー名の列挙。

**件数が少ない**（0〜数件）ときは、傾向を**断定せず**、聴取で確認できた事実を優先する。

   - **必須ルール：** おすすめ側3項目のうち、**少なくとも1項目はシチュエーション適性**（例：添い寝・同棲・お泊まり・主従・年上年下など）を明示する。  
   - **内容の軸（既定寄り）**：おすすめ側は「距離感の嗜好（超近接など）／演技の質感（リアル系・アニメ系）／音響の指向性」を優先、合わない側は「ノイズ耐性／特定シチュへの嫌悪／物語テンポとの不一致」を優先する。

4. **グラフ評価内訳（五軸・2026-05-20）**  
   催眠のトランス／快楽／満足の三軸は**使わない**。同人は次の**五軸**で記述する（レーダー画像は `schemaVersion: 2`・`_分析データ.json` の五スコアと一致）。**十サブ見出しの正式名は下表に固定**（略称・旧称への差し替え禁止）。

   | 軸（表示・レーダー順） | サブ見出し（各2つ・計10） | 物差し |
   |------------------------|---------------------------|--------|
   | **シナリオ** | **リアリティ**／**展開の必然性** | 関係・台詞・キャラの自然さ／段階が自然につながり唐突さが少ないか |
   | **音響** | **マイク・録音品質**／**環境音** | 機材・S/N・クリップ・吐息のクリアさ／水音・布擦れ等の配置と台詞・情景との関係 |
   | **没入度** | **空間定位・音像**／**距離感・密着度** | 左右移動・定位の滑らかさ・音像の追いやすさ／章を跨いでも耳元など距離基準がブレないか |
   | **快楽度** | **演技力**／**刺激のテンポ・緩急** | 声色の落差・呼び名の段階・キャラの一貫性（催眠向けの下品語・カウントは**該当作品のみ**同義で可）／関係と快感の山・ピーク・間の設計 |
   | **満足度** | **コンセプトの達成度**／**余韻の質** | タイトル・販売説明の約束が最後まで薄まらないか／聴後に密着感・想起・就寝導線などが残るか |

   **表示フォーマット（`index.md`）**  
   - 軸行 … `- **{軸名} n（{サブA} n / {サブB} n）**`（例：`- **シナリオ 9（リアリティ 9 / 展開の必然性 9）**`）  
   - 小見出し … `**リアリティ**` のように**上表の正式名**をそのまま使う（括弧付き別名は付けない）。  
   - **並び** … 本文の五軸ブロックは上表の①〜⑤の論理順（**シナリオ→音響→没入度→快楽度→満足度**）でよい。レーダーラベル順は **没入度→シナリオ→快楽度→音響→満足度**（`generate_review_triangle.py` v2）。  
   - **`_分析データ.json`** … `schemaVersion: 2`・`scores`: `immersion`／`scenario`／`pleasure`／`acoustic`／`satisfaction`。

5. **パート解説（フォーカス変更）**  
   誘導手続きの説明より、**音響演出の意図**と**演技の機序**を優先する。  
   - 解析で答える問い：なぜこのタイミングで耳元移動か／なぜこの効果音か  
   - **第三段落**  
     - **心身の反応（上級・熱量トーン）：** どの帯域が前景か、どの場面で情動の段が切り替わるか等、**観測語**で書く。生々しい身体反応の列挙に寄せすぎない。  
     - **`体感:`（既定）：** 定位・関係の移り変わり・刺激の強さが**身体にどう残るか**（§3h 項5）。検証可能な事実は体感の一文に織り込む（上記「事実・実用性への特化」）。

6. **総評：本作品の結論**  
   「誘導成功」ではなく、**音響作品としての設計精度**（録音・演技・脚本の整合）で締める。見出し・三柱の細則は本ファイル「`## 総評：本作品の結論`（上級・追記）」を参照。

### 特殊同人（探索型・分岐型オナサポ）運用（2026-05 追記）

`レベルアップ式オナサポダンジョン ～レベルを上げて最高の射精を目指す探索型オナサポゲーム～` の分析データで確定した、**ゲーム構造を持つ同人音声**向けの仮ルール。通常の「一本道トラック作品」と同じ書き方をすると、読者が誤解しやすい。

1. **レビュー冒頭で「作品の型」を先に宣言する**  
   - まず「探索型」「分岐あり」「失敗ルートあり」「到達レベルでエンディング変化」など、**体験の前提**を1〜2文で明示する。  
   - ただし本文で「攻略wiki」のように細かい手順を列挙しすぎない。**購入判断に必要な難易度情報**を優先する。

2. **パートの並べ方は「時系列」より「機能別」を優先する**  
   この型はファイル数が多いため、`## パート解説` は次の機能単位でまとめる（個別トラックは必要箇所だけ引用）。  
   - スタート地点（ルール説明）  
   - 中間地点（必須課題）  
   - レベリングルーム（任意課題・レベル加算）  
   - ゴール地点（最終寸止め・振り分け）  
   - クリア地点（レベル帯エンディング）  
   - 失敗時音声（暴発／ギブアップ・命令無視）

3. **「必須課題」と「任意課題」を混同しない**  
   - 中間地点のオナサポは**進行必須**。  
   - レベリングルームは**任意**だが、クリア時レベルに直結する。  
   - この区別を曖昧にすると、読者が「どこまでやれば作品の設計意図に乗るか」を判断できない。

4. **失敗系トラック（暴発・ギブアップ）を軽視しない**  
   - 失敗音声は蛇足ではなく、**緊張維持の装置**として評価対象に入れる。  
   - ただし「罵倒の強さ」だけで点数を決めない。  
   - 見るべきは、失敗時の文言が本編ルール（命令遵守・寸止め維持・再挑戦導線）と整合しているか。

5. **評価軸に「ルート設計の明瞭さ」を追加で見る**  
   既存三軸（没入／刺激／満足）に加えて、探索型では次を本文で必ず触れる。  
   - どこで分岐するかが分かるか  
   - レベル条件と到達先（例：クリア地点1〜4）の関係が読者に伝わるか  
   - 再挑戦時に迷子になりにくいか（ガイド音声・フォルダ導線）

6. **総合評価の根拠は「一本の最適ルート」前提にしない**  
   - 高レベル到達の快感だけを基準にせず、**通常到達・失敗到達の体験品質**も含めて評価する。  
   - 「完走難易度が高いほど高得点」という運用は禁止。  
   - 難しい作品でも、導線が不親切なら減点対象。

7. **おすすめ欄は「嗜好」だけでなく「運用適性」を入れる**  
   `おすすめしたい方` の3項目のうち最低1項目は、次のような**運用条件**を書く。  
   - ルール音声を聞いて段取りどおり進めるのが苦にならない  
   - 分岐・再挑戦を前提に反復プレイできる  
   - 失敗ルート込みで世界観を楽しめる  
   `合わない可能性がある方` には、短時間回収志向や手順読み飛ばし傾向を明示する。

8. **本文に入れない情報（メタ）の明確化**  
   - `info.txt` のアフィリエイトURL、クーポン有無、体験版有無は、本文に直書きしない（既存運用どおり）。  
   - 解析素材のファイルパス列挙も本文禁止。必要なら `_分析データ.json` の `notes` へ。
   - **DLsite の製品ID（例：`RJ01617970`）を本文に書かない。** 製品IDはファイル管理・連携用の識別子として扱い、公開本文では作品名・サークル名で記述する（`dlsiteProductId` フィールドは維持してよい）。

9. **この型での「パート第三段落」は `体感:`**  
   - 通常作よりトラック本数が多く、読者は関係の変化や刺激の移り変わりを**身体感覚で追いたい**。  
   - 第三段落は **`体感:`**（§3h 項5）。休憩の目安・定位の安定などの事実は、**体感の一文に織り込む**。

10. **`title` の `【レビュー】` 前置（サイト一覧・標準寄り）**  
    - **`title`** を **`【レビュー】＋商品タイトル`** とする（末尾に「レビュー」を再度付ける必要はない）。**探索型・一本道シチュボイスを問わず**これで統一してよい。  
    - **`itemName`** は販売ページの商品名を維持し、変更しない（真執筆ガイド §1（補）項1 と同じ）。
11. **比較視聴の価値を正当に評価する（改定基準）**
    - 2周目・3周目で差分が効く設計は、**作品固有の完成度**として積極的に評価してよい。  
    - 判定時は「単ルート1周で完結するか」を必須条件にしない。**比較で成立する強み**（分岐差・再挑戦性・ルート設計）を総合の根拠に含める。  
    - ただし、比較が前提であることは `## 総合評価` と `_分析データ.json` `notes` で明示し、読者が誤読しないようにする。

### 評価時の視聴前提（固定）

- **総合評価　静かな環境で視聴する場合の評価** … 同人レビューの総合評価は、この見出し文言（または同義の明示）を基準に、**静かな部屋で一人、イヤホン／ヘッドホン視聴**を前提として記述する。  
- 同人レビューの採点は、**静かな部屋で一人、イヤホン／ヘッドホン視聴**を基準条件とする。  
- 生活騒音・通勤環境・スピーカー再生などの差は、原則として点数の主因にしない（必要なら `体感:` やおすすめ／合わないで注意喚起）。  
- 例外的な再生条件でのみ成立する強み（爆音前提など）は、総合の根拠に据えない。

### 事実・実用性への特化（2026-05 追記・標準寄せ）

長尺シチュボイスや近接録音では、**読者が再現できない主観の羅列**より、**誰でも検証しやすい事実と実利**を優先する。`dakimakura-kanojo-pretty-holic-yurukawa-kouhai` 改稿で整理した次の3点を、同人レビューの**既定寄り**として扱う。

1. **「きもい」描写を客観的な事実へ**  
   - **避ける例：** 眼瞼下垂、特定筋の収縮、局所の生々しい反応の列挙など、医学・解剖に寄りすぎた身体ログ。  
   - **推奨：** **聴き疲れ・中断のしにくさ**、定位やミックスが**長尺でも破綻しにくい**ことなど、生活実感または耳で検証できる語。**自律神経・入眠**など幅広い生理語は、**パート名やタイトルが既に約束している内容の言い換え**にしない（→ 下記「タイトル・トラック名と重複する断言」）。  
   - **耳・機材側で書いてよいこと：** 帯域・定位・ノイズフロア・音量バランス・S/N（読み取れる範囲の事実ベース）。

**タイトル・トラック名と重複する断言は書かない（重要・完成度に直結）**  
**入眠用／安眠／リラックス**など、販売側が既に書いている効果を、そのまま繰り返して段落を終えない。**読者が怖い落差**（高刺激の直後の急転換、角の立つSE、名目だけのパート）を起点に、**音量・密度・編集・勾配**など音声の事実で、タイトルやトラックリストの**約束と実装がつながっているか**を書く。実例の書き分けは `dakimakura-kanojo-pretty-holic-yurukawa-kouhai` の **【安眠用】キス** パートの `体感:` を参照。

### 本編と【安眠用】等の特別パート（2026-05-20・`docs/真催眠音声執筆ガイド.md` §1（補）④ と同一）

| 区分 | 扱い |
|------|------|
| **本編** | シチュの**関係進行・本番・タイトルが売る主軸**が載るトラック。`summary`・グラフ・おすすめの**主評価は本編基準**。 |
| **【安眠用】・【入眠用】・寝落ち救済** 等 | **本編の物語・近接演技とは別枠**（終端・休息）として切り分ける。**本編と同一の「1章」として混ぜない**。 |
| **フリートーク・NG集** | 採点・読者本文から**除外**（`review-audio-work-only-scoring.mdc`）。 |

**採点** … 【安眠用】等は**作品の一部**なので、**満足度（コンセプトの達成度・余韻の質）・快楽度（刺激のテンポ・緩急）**などに**反映してよい**。**没入・快楽の主根拠を安眠パートの尺だけ**にしない。

**安眠用の「説明」が書ける場所（厳守）**

- **書いてよい** … **`## パート解説`** の**当該見出し直下のみ**（例：`### 【安眠用】キス` の `内容:`／`体感:`）。催眠側は **`## パート別解析`** の同名見出し。
- **`### パートの長さ`** … 公式パート名・尺の**列挙のみ**（説明文は付けない）。**先頭の合計行は本編のみ**（【安眠用】等は合計に含めない・明細は別行）。
- **書かない** … **`summary`・`itemDescription`・`グラフ評価内訳`・おすすめ／合わない・総評** への **【安眠用】ラベル**および**内容・音響の説明**。グラフの着地・余韻は **「終盤」「終端処理」** など一般語にとどめ、**固有の描写はパート解説へ**。

**散文**

- **禁止** … 写真の `summary` のように、**カード冒頭・グラフ・総評**に安眠の帯域処理やキス終端を書く。
- **推奨** … `summary` は**本編の段取り→通し尺**のみ。安眠の落差・ミックスは **`### 【安眠用】…` ブロックだけ**で書く。  
  **見本:** `dakimakura-kanojo-pretty-holic-yurukawa-kouhai`（`summary` は本編まで／安眠は `### 【安眠用】キス` のみ）。

2. **「上から目線」をユーザー視点のメリットへ**  
   - **避ける例：** 「〜を評価する」「完成度が高い」とだけ断言する**評論者スタンス**。  
   - **推奨：** **試聴条件を明示**したうえでのチェックリスト調。**長時間でも姿勢・音量で続けられるか**、**販売ページの総再生時間（例：162分）に対してタイトルどおりの流れが薄まらないか**、環境ノイズに弱い耳でも破綻しないか、など**購入前に知りたい項目**で書く。  
   - **グラフ内訳**の見出しは、現行フォーマットでは **`グラフ内訳`** を既定とする。必要がある場合のみ補助ラベルを追加する。

3. **「そそる」表現を、音響・物理の確信へ**  
   - **避ける例：** 誘惑・煽りだけで終わる形容。  
   - **推奨：** **音響のノイズが目立たない**、**定位がトラックをまたいでもブレにくい**、**終盤で刺激を落とし入眠導線がある**など、**再現性のある品質の事実**で「失敗しにくい」と読者に伝える。
4. **録音品質の足切りライン（辛口・明文化）**
   - 次のいずれかが**持続的**に見られる場合は、三軸・総合を厳しめに下げる：  
     - 台詞の聞き取りを妨げるノイズ（ヒス、ハム、歪み、過度なクリップ）  
     - 定位が不自然に揺れて場面把握を阻害する編集  
     - 帯域マスクで台詞と効果音が恒常的に競合するミックス  
   - 一過性の軽微ノイズは本文注意で済ませてもよいが、**没入・刺激・満足の根拠には使わない**。  
   - 「構成が良いから録音難を相殺する」運用はしない。**聴取阻害は完成度欠点として独立扱い**にする。

**パート解説の第三段落（`体感:`）で書くことの例：** 耳元の近さが身体にどう残るか、関係の移り変わりが胸や喉にどう伝わるか、**本編から終盤への落差**を聴いたときの安心／緊張の変化（「安眠だから眠れる」の繰り返しではなく、帯域・音量の落差が身体にどう感じられるか）。定位・ノイズ等の事実は**体感の一文に織り込む**。

### シチュエーション（主要フェチ）定義（2026-05-20）

**目的** … 作品データ（タイトル・タグ・`summary`・パート名・台本の関係性）から **【シチュエーション（主要フェチ）】** の要素だけを抽出し、下記ルールで整形して **`quickGuideBySlug`** に載せる。

**出力フォーマット（正本）**

```text
主要フェチ：[整形後のタグを「 / 」区切りで最大4つ]
```

- **コード上** … `page.tsx` の **`majorFetish`**（クイック【スペック表】の **「主要フェチ：」** 行）。
- **同人UIの「シチュエーション：」行** … 表示ラベルは **シチュエーション** だが、**同じ整形ルール**で **`inductionType`** に書く。**最大3つ**（行の運用枠。4つ目は `majorFetish` 側へ）。

#### 定義ルール（厳守）

**1. 表記の統一と無駄な修飾語の排除**

サイト固有・レビュー固有の修飾語は **標準名詞** に落とす。

| 元の言い回し（例） | 統一後 |
|--------------------|--------|
| 恋人一本道・恋人進行・甘々恋人 | **恋人** |
| ゆるカワ後輩・後輩からかい | **後輩** |
| 温泉・旅館・お泊まり温泉 | **温泉**／**旅館**／**お泊まり**（該当する方だけ） |
| ポキポキ睡眠導入・整骨 | **ポキポキ** |
| 密着添い寝・ぎゅっと密着 | **添い寝**（抱き枕が主なら **抱き枕** を優先） |
| 〇〇シチュ・シチュボイス | **該当する場面名**（`シチュ` 接尾辞は付けない） |

**2. 優先的に抽出・分類すべきコア・シチュエーション**

元データに含まれる要素は、可能な限り次の **標準タグ** に寄せる（該当がなければ **短い一般名詞** を新規に付けてよいが、**長い修飾句・造語は禁止**）。

| 区分 | 標準タグ（一覧） |
|------|------------------|
| **関係・役割** | 後輩 / 先輩 / 恋人 / 幼馴染 / 同級生 / 姉 / 妹 / メイド / 上司部下 |
| **場面・行為** | 抱き枕 / 添い寝 / 膝枕 / デート / お泊まり / ラブホ / 同棲 |
| **場所・雰囲気** | 学園 / 温泉 / 足湯 / 旅館 / 自宅 |
| **音響系シチュ** | 耳かき / ポキポキ / マッサージ |

### パート解説の文体（§3h の同人版・`docs/真催眠音声執筆ガイド.md` §3h 転用）

#### 1. ブロック構成（固定）

#### 2. トーン（人間味）— §3h 項2 転用

- **基調** … ブログレビューとして伝わる**丁寧なです・ます調**（`内容:` の各文）。

- **批評眼（必須・`内容:` に1箇所以上）** … 仕様列挙だけでなく、**制作者の意図が伝わる一文**を**少なくとも1パート**に入れる。

#### 3. `内容:` の型（音響作品・§3h 項3・4 転用）

- **型** … 「（パート名）では「作中セリフ」の〜で、（演技・ミックス・SE）が〜ます。（因果の2文目）。」

#### 4. `体感:` — §3h 項5 転用（`身体の反応:` と同一物差し）

AI が **`体感:`** を書くとき、**仕様書調の冷たい語**と**ねじれた AI ポエム**を**双方とも禁止**する。

- **一至二文** … 聴き手の肉体・意識に起きる変化を、**優しい主観的な日常語**で、**現在進行形**で閉じる（`〜ていきます` `〜してきます` 等）。
- **推奨語** … じわじわ、じんわり、ぼんやり、ドキドキ、ぽかぽか、力が抜ける、熱くなる 等（作品に即して差し替え可）。**`じわじわ`＋`寄る` の結合は禁止**。
- **禁止語尾** … `〜のが分かります` `〜感じられます` `〜がみられます` `〜と観測されます`。
- **禁止語彙** … §1（補）の **`立ち上が` 系・`引きずる` 系・`じわじわ寄る` 系**、仕様書調（態勢が整う、物理的脱力、処理が完了する 等）、AIポエム（意識がハメ込まれる、深度が更新される 等）。
- **メタの書き方** … 定位・ノイズ・休憩位置など**検証可能な事実**は、**体感の一文のなかで**身体感覚と結びつけて書く（第三段落を機材スペック一覧だけで終えない）。**`挟みやすい` だけ**で終わらせない（§3e 項8）。

**標本（同人）** … `dakimakura-kanojo-pretty-holic-yurukawa-kouhai` の `## パート解説`。

### 敬体・リズム（§3f の同人転用）

- **基調** … **です・ます**の丁寧語（常体のねじれ禁止）。
- **許可語尾** … `です` `ます` `てしまいます` `ていきます`（**`体感:`・グラフ2文目**は進行形を優先）。

## 論理と体感のつなぎ方

**並列ラベル（「論理：」「体感：」だけの並べ方）は避ける。** パッチワークに見えやすい。

| 方針 | 書き方 |
|------|--------|
| **推奨** | 定位・脚本などの事実 **だからこそ**、耳／自律神経／注意がこうなる、と**因果で一行にまとめる**。 |
| **ミクロな錯覚** | 「没入した」より、**イヤホンコードのこすれを寝返りに錯覚した**など、物理ノイズが作品側に書き換わった瞬間を書く。 |
| **語彙** | 「ドーパミンがガチャガチャ」など **擬音＋神経語の乱用**は避ける。**報酬予測・交感／副交感・帯域・テンポ**でトーンを揃える。 |

## 分析→破壊のサイクル（黄金パターン・任意）

長編シチュボイスで **論理で構えて快感で壊す**ときの推奨フロー。正本の同名節と内容は対応させ、**詳細はこちらを参照**。  
**★9〜10** での熱量レビュー向け。**★8 以下**では原則使わず、**構成説明・`体感:`**で足りる。  
**注意：** **事実・実用性への特化**で書く回では、敗北・毒性・無様な渇望の強調は**必須にしない**。同じ実例ファイルでも、トーンは企画・読者層で切り替える。

1. **構築** … 声道・帯域・交感／副交感・性的勾配など、読める範囲で論理を立てる。
2. **ミクロ官能** … **特定キャストの一拍の呼吸・吐息**で刺す。キャスト名＋**決め台詞の直後**が効きやすい。
3. **刺激度で崩壊** … 理屈が続かない瞬間を明示する。続けて **シャットダウン後の無様な主観**を一行（例：分析が **「もっと聴かせろ」と喉だけが騒ぐ渇望**に落ちる）。**交感が最高だった区間**と**言語が崩れたトリガー**も書く。
4. **満足度** … 約束の回収に加え、**期待の質の変質**。**現実へ戻る手順が浮かばない毒性**。それでも **翌日また再生する**不可逆を一文。
5. **感想** … 「設計図への敗北」より、**仕事が手につかない／責任の所在／理性が快感に破壊された**など生々しく。**執筆時の身体ノイズ**（吐息が残りキーが慎重になる等）を一行。

**実例：** `src/content/レビュー/dakimakura-kanojo-pretty-holic-yurukawa-kouhai/index.md`（随時更新）

## `## 総合評価` の書き方（上級・追記）

正本「`## 総合評価` の書き方（同人専用）」に**加える**ときのメモ。

- **事実・実用特化** … 見出しは `## 総合評価` を固定し、直下は星評価から開始する。必要なら補助ラベルを置けるが、現行実例では **`**グラフ内訳**`** を標準とする。
- **星の根拠** … 「約束どおり」だけに寄せない。**その音声で管理人がどう溶けたか**を軸語に寄せてよい（**実用特化の回では**「ページの約束が尺のせいで薄まらなかったか」等、読者メリットで書く）。
- **没入度** … 脚本の整合に加え、**現実の部屋をいつ・どこで忘れたか**をミクロに。
- **刺激度** … 勾配の理屈のあと、**本能側への落下**を必ず一行。
- **満足度** … 約束回収だけにしない。**放心・多幸感の重さ・毒性・再生依存**まで踏み込めるなら踏む。

## `## パート解説`（上級・追記）

正本「`## パート解説`」に**加える**ときのメモ。

- **事実・実用特化** … 見出しは **`## パート解説`** を標準とする。第三段落は **`体感:`** で統一（§3h 項5）。定位・落差・関係の移り変わりは**身体感覚と結びつけて**書く。**パート名との効果の言い換えだけ**で終えない（「タイトル・トラック名と重複する断言」節）。
- **耳の感覚を先に** … 「SE が増える」だけにしない。**湿り・粘度・無音の長さ・歯擦音のマスク・定位の周期**など、耳が受けた変化から書く。
- **キャストに固執** … 抽象の音響語より、**決め台詞のあとの一息・吸気**を拾う。
- **スタンス** … 見出し直下に一言、**演技論よりひれ伏し側のログである**と置いてよい。

## `## 総評：本作品の結論`（上級・追記）

同人レビュー実用寄せの総評ブロック。**催眠ルート B 正本**は `docs/真催眠音声執筆ガイド.md` の `## 総評：本作品の構造的結論` に従う。

- **標準見出し** … **`## 総評：本作品の結論`** を使用する（**催眠側ルート B** の `## 総評：本作品の構造的結論` とは別。同人ではこちらの一行固定）。
- **標準三柱** … 直下に `### 【設計の要点】` / `### 【音響面の精度】` / `### 【結論】` をこの順で置く。
- **体裁方針** … **`## 作品感想` は設けない。** 購入判断や読後の総括は三柱の `### 【結論】` までに収める（一人称・挨拶で末尾が感想ルートに見えるのを避ける）。聴取体感は `## パート解説` の **`体感:`** に集約する。

## 禁則・ダメ例（ワークショップ）

上記 **「文体ルール（真執筆ガイド準拠・同人転用）」** と `docs/真催眠音声執筆ガイド.md` §3e の重複を避け、**同人執筆で再発しやすいNG**を表にまとめる。

| NG | 理由 |
|----|------|
| 「正直に言います」「マジで」「ずるい」「距離感バグ」の連発だけ | 安いエモのパッチワークに見える。 |
| 「ディスプレイが視界に入らない」だけ | 定型で読み飛ばされる。ミクロな錯覚を優先。 |
| 「解析フォルダ」「文字起こし参照」など | 読者向けメタ。**`_分析データ.json` の `notes`** に限定。 |
| 眼瞼下垂・骨盤底・皮膚温など、**検証不能な身体ログの密度勝負**（事実・実用特化の回） | 医学っぽさだけが残り、実務的な購入判断に繋がらない。自律神経・入眠・定位・S/N に寄せる。 |
| 「〜を評価した」「完成度は極めて高い」等、**根拠なしの評論者口調**だけ | 読者メリットが見えない。**試聴条件＋チェック結果**で書く。 |
| 「挟みやすい」「入れやすい」「〜しやすいです」だけで文や段落を終える | **何を挟む／置く／基準にするか**が欠け、読者が操作や順序を復元できない。**休憩・分割再生・音量判断など、聴き手の具体動作**まで書く（`.cursor/rules/review-prose-voice.mdc` と `docs/真催眠音声執筆ガイド.md` §3e 項8 と整合）。 |
| **「主菜」** で構成や快感の軸を言う | 献立メタになりやすい。**軸・中心・土台・主眼・前景**で書く（§3e 項9・`review-prose-voice.mdc`）。 |
| 「いきなり尖らず」のような語感先行の表現で流れを説明する | 何がどう急にならないかが不明で読み手に解釈を委ねすぎる。**刺激・SE・帯域・会話テンポ**のどれを指すかを丁寧に書く（§3e 項10・`review-prose-voice.mdc`）。 |
