### 0.1.1 用語：ドライオーガズムと脳イキ（別物・混同禁止）

**生物学的・サイト内の整理どおり、別の現象として書く。** 読者向け本文・`SUMMARY`・おすすめ・グラフ内訳・総評で **同義扱い・括弧併記・言い換えのすり替えをしない。**

| 用語 | 書くときの意味（要約） |
|------|------------------------|
| **脳イキ** | 頭内の快感・想像／確信が中心。**射精を伴わない頭の高揚**（「頭が真っ白」「頭の奥が締まる」等）。快感の主戦場は**頭側**の系統名。 |
| **ドライオーガズム** | **射精を伴わず**、副交感神経優位のまま**全身**に快感が循環・波状に続く絶頂。台本・販売が「ドライ」と明言しているときは**こちらを主語**にする。 |

**禁止（新規・改稿）**

- `ドライオーガズム（脳イキ）` `脳イキ＝ドライ` `脳イキ型のドライ` など **同一視の括弧・等号・言い換え**
- ドライ専売作のリード・おすすめ・快感総評で、**脳イキだけ**を絶頂の正体にする書き方（台本が「ドライオーガズム」と言っている箇所は **ドライオーガズム** と書く）
- 採点メモの「脳イキ型」ステージ語を、**読者向け散文にそのまま貼る**こと（必要なら体感で言い直す）

**許容・使い分け**

- **両方**が作品の売りなら、`tags` や種類行で **並列**（例: `口腔催眠・脳イキ`／別行で `ドライ`）。**1語に畳めない**
- **体験感度Lv**の `脳イキは可能（ドライ絶頂は未達）` は **段階の対比**として正しい（脳イキが先、ドライはその先）。この2語を別物として並べる用法
- **絶頂回数行（総合評価・クイック表示）** … `**ドライシーン n回**`・`**ウェットシーン n回**`（または `複数回`）は **回数表記のみ**。**直後の全角括弧は一切付けない**（2026-05-28 追記）。例: `ドライシーン複数回（我慢ゲームの10→0・乳首弾き絶頂）` `ウェットシーン1回（ごめんなさいカウント射精）` `（ドライオーガズム）` はすべて禁止。内訳・場面名・イき方の説明は `tags`・種類行・おすすめ・本文・主要誘導へ回す。`_分析データ.json` の `orgasmSummary` も同じ（括弧なし）。`docs/レビュー三軸評価定義.md`・`review-prose-voice.mdc` と整合
- 深掘り … サイト記事 [`dry-orgasm-what-is`](/reviews/dry-orgasm-what-is/)（脳イキとの対比）

### 0.5 【本作の誘導・暗示解析詳細】相当 → 四表 ＋ `INDUCTION_FLOW`

- **全作品**で `誘導方法`・`身体の変化` は `_分析データ.json` の三軸・総合評価と**整合**させる（§4.5）。弱点はお世辞なくファクトで書く。

```
#### N. 呼吸誘導で受容の土台を作る

**誘導方法:** …
**身体の変化:** ゆっくりした呼気が続くと副交感神経が優位になり、覚醒系の緊張が下がります。その結果、心拍と呼吸が落ち着き、肩の力が抜けて「聞くだけでよい」受容感が広がっていきます。
```

### 快楽度の物差し — 催眠としての気持ちよさ（2026-05-29）

**快楽度**は、一般エロ音声の**性的実演の強さ**や**ウェット回収の多さ**を主軸にしない。**催眠として聴いたときの気持ちよさ**に**かなりの比重**を置く。

| 主に見る（加点） | 補助（作品の C-0 に合わせる） |
|------------------|-------------------------------|
| 暗示・誘導が**身体感覚に届く**快さ（熱・締まり・ゾクッ・頭内の高揚など） | 作品が主に売る快感経路（禁止反転・ドライ・カウント等） |
| **トランス状態の心地よさ**（脱力・浮遊・受容・声に乗る感覚） | トリガー・反復刷り込みの報酬感 |
| **声・間・ペーシング・バイノーラル**での気持ちよさ | 条件づけが効いたときの脳内の報酬 |

| 単独では上げない／大幅に控えめ | 理由 |
|-------------------------------|------|
| R18 実演・射精描写の**多さ・音量・回数だけ** | 催眠の快楽軸とずれる |
| トランスが薄いまま**物理刺激だけ**が続く区間 | 没入の上に乗る報酬にならない |
| 喘ぎ・淫声の**派手さだけ** | 同上 |

**トランス連動（既存表と整合）** … トランスが薄い作品は、**催眠としての快楽の厚みも上限が低くなる**（5.9 以下連動）。実演が長くても、**快楽度だけを押し上げない**。

**本文（グラフ評価内訳・総評）** … 快楽行は **部位→感覚**（§7.1）に加え、**催眠としてどこが気持ちいいか**を先に書く。ウェット回収の列挙だけで 6 点台にしない。

## 4. 主要誘導の流れ（作品の流れ）— 執筆の核心

### 4.1 1手順のブロック構造（この順・このラベル厳守）

```markdown
**誘導方法:** {使った技法・手続き。括弧で技法名を添えてよい}
```

**空行必須（記事モード表示・再発防止）** … 見本は `kuchikou-saimin-count-trip-nouiki`。**`####` の直後・引用ブロックの直後・誘導方法の直後**にそれぞれ **空行1行**。空行が無いとサイト上で **見出しと引用だけ**が表示され、`誘導方法`／`身体の変化` が引用に吸い込まれる。**マージ時** `auto_review.py` の `normalize_induction_flow()` でも補正する。

### 4.2 見出し（`#### N.` の右側）

| 禁止 | 推奨 |
|------|------|
| `導入` `暗示` `エッチ` `解除` など工程ラベルのみ | `呼吸誘導で受容の土台を作る` のように **技法＋目的** |
| 抽象語だけ | 作品固有の手順名（逆カウント / 一時覚醒比較 / 口唇感覚集中 等） |

### 4.3 引用（`>` 行）

- **WhisperX 出力に実在する文のみ。** 要約・言い換え・創作禁止。
- **1手順あたり1〜3文・おおよそ80〜200字。** Whisper の連結全文をそのまま貼らない。核心の一句〜三句に切り出す。

- 手順の核心が伝わる箇所を選ぶ（カウント、キーワード、体感の宣言）。
- 引用の直前後に空行を1行入れる（見本どおり）。

### 4.4 誘導方法

- **何をどう誘導したか**（技法名・手続き・反復・カウントの役割）。
- 読者向けに専門用語は必要最小限。連発しない。
- 例: `ゆっくりした吸気・呼気の指示と、手足を投げ出す脱力描写（呼吸誘導）。`

### 4.5 身体の変化（体内メカニズム → 体感）— 正本

**読者に伝えること:** その手順の誘導のあと、**身体の中で何が起きているか**（自律神経・血流・**ドーパミン**等）と、**身体に実際に起きる体感**を**必ずセット**で書く。**メルティ型**（`futarigake-saimin-melty-orgasm`）と同じ作り。**体感だけ・メカニズムだけは禁止**（平易化のあとも本節を維持）。

| 軸 | 1文目（加点要因） | 2文目（伸びしろ・減点） |

- **U+2014 ダッシュ（`——`）は使わない** … 句点（`。`）で区切る（Windows 等で文字化けしやすい）。
- **サークル名・声優名（CV）・「○○氏」** … 感想本文に載せない（§8.4 と同じ）。

**Gemini 再実行**

| 用途 | コマンド |
|------|----------|
| 新規 | `generate_work_impression.py <slug> --write-tsx` |
| 文体・主観の修正 | `--revise --write-tsx --note "§8.4.2参照"` |
| digest だけ更新 | `--refresh-dlsite-digest` のあと `--write-tsx` |

**人手修正の位置づけ** … Gemini 出力の**仕上げ**（禁止語・語尾・4段落維持）のみ可。**白紙から手書きで感想を書かない**。`--write-tsx` 後も `npm run review:validate-prose -- --slug <slug>` で確認。
