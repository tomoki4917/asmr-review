# レビュー執筆・採点運用ガイド（評価基準と作成手順）

この文書は、**管理人・編集担当・執筆支援（AI 含む）**がレビューを「同じ物差し」で進めるための**運用まとめ**です。細目の定義は **`docs/レビュー三軸評価定義.md` が正本**であり、ここでは**決めごとと手順**を優先して書きます。

---

## 1. 評価が対象としているもの

- **対象**：同人・商業の**催眠音声**を、**鑑賞用レビュー**として評価する。
- **明示しないこと**：臨床催眠の効果検証や治療適性は**保証しない**（三軸定義どおり）。
- **語の置き方**：「催眠」「トランス」は娯楽の口語だけにせず、学習で扱う範囲の意味に寄せて書く努力をする。

---

## 2. トランスありき（本サイトの標準）

読者向け本文に見出しを足す必要はない。**編集・`_分析データ.json`・レビュアー内部の物差し**としてだけ使う。

1. **まず `scores.trance`（トランス度）を決める。**  
   誘導・暗示・没入が薄いと判断したとき、**快楽度・満足度だけを極端に高くしない**（読者から見て「催眠レビュー」の説得力が落ちる）。
2. **快楽度**は、「催眠として提案が届いている」と読める状態を前提にした**報酬設計**として読む。
3. **満足度**は、その催眠体験の**着地・約束の回収**として読む（一般エロ音声と横並びにしない）。
4. **例外**：作品が催眠とは別コンセプトを前面にしているときのみ、軸どうしのずれを許容してよい。そのときは **`_分析データ.json` の `notes` に理由を一文書く**。

**トランス度（レーン別4次元）** … `eval_trance_rubric.md`。5レーン（深化／受容・支配／感覚／トリガー／薄い催眠）→ 入り・深さ・暗示の効き・維持 → レーン別重み合成。

**快楽度（C-0別4次元）** … `eval_pleasure_rubric.md`。C-0（脳イキ／情緒／堕落／ドライ／トリガー／その他）→ 整合・刺激・クライマックス・起伏 → C-0別重み。既決トランスを超えない。

**満足度（4次元）** … `eval_satisfaction_rubric.md`。約束の着地・解除・余韻・尺対密度 → 固定重み合成。

`_分析データ.json` に `tranceScoring` / `pleasureScoring` / `satisfactionScoring`（次元点・レーン/C-0）を保存。読者向け `index.md` にはレーン名を出さない。

参照：`.cursor/rules/review-trance-first-scoring.mdc`、`eval_trance_rubric.md` 他。

## 3. 三軸の意味（短く）

| 軸 | 見ること（要点） |
|----|------------------|
| **トランス度** | 暗示・誘導への没入の深さ、台本が注意を内向きにどこまで引けるか。**「催眠の体裁」だけで加点しない。** エロ報酬が主で没入が浅いと感じる場合は下がりやすい。 |
| **快楽度** | **その作品が売っている快感のコンセプト（C-0）**に対して、期待と報酬・反復設計が筋通りか。**喘ぎの多さだけで並べない。** |
| **満足度** | **解除・余韻・着地**。「気に入ったか」の総合満足と同義にしない。**尺に見合う密度・締め**もここに含める（長尺は長尺の評価軸で）。 |

**性癖中立（全軸共通・2026-07）** … NTR・女体化・凌辱・輪姦など**題材そのもの**を加点・減点の理由にしない。三軸は常に**催眠体験・催眠的快楽体験・快楽体験の品質**だけを測る。背徳感・屈辱が快感の燃料として機能しているなら刺激設計として評価し、「人を選ぶ」「万人受けしない」を減点理由に書かない。正本は `docs/レビュー三軸評価定義.md` の「性癖・題材で上げ下げしない」。

**観念としての「入り」と「深さ」** … 消えていません。**正本の `docs/レビュー三軸評価定義.md`** では、トランス度を見るとき **深さ**に加え **乗るまでの手厚さ**（導入・補助・前処理）と **本編を通した型・戻り**を一体として書いています（「執筆上の三軸の扱い」）。記事本文で **`入り`／`深さ`** とラベルを付けるのは **執筆上の省略記法**であり、`docs/真催眠音声執筆ガイド.md` §1（補）項5 の **グラフ軸行** に **`トランス度 n（入り x / 深さ y）`** と **推奨**として載っています（同ファイルに **快楽度：快感設計／絶頂シーン**、**満足度：着地／余韻** の併記例あり。**快楽度**の括弧内の共通定義は、**快感設計＝絶頂へ至る「焦らしと高まり」の設計**、**絶頂シーン＝絶頂局面そのものの設計・終端回収**（旧ラベル「ピーク回収」から改称・2026-05））。実例：`src/content/レビュー/nouiki-trip-denpa-live/index.md` の `## 総合評価`。すべてのレビューがこの形式である必要はなく、短く書いた記事では一行にまとめるだけの場合もあります。

詳細・チェック表は **`docs/レビュー三軸評価定義.md`** の A〜D と C-0 の成功定義を見る。

## 4. 総合の星（`ratingValue`）

- **三軸の単純平均を機械的に必須としない。**  
  偏りがあるときは本文・`notes` で読者が納得できるように書く。
- 星を付けるときは、三軸に加えて **作品としての完成度**（構成・表記と実体の一致・制作の破綻の有無）を必ず頭に置く（定義書「総合の星を付けるときの判断材料」）。
- **本文では**、「想定読者は…」など**採点のメタ注釈**を `## 総合評価` に書かない。物差しはこのドキュメントと定義書に置く。

### 4a. 総合の星と冒頭（`summary`）口調（2026-05）

**一覧カードに載る `summary` の義務**は、**総合 `ratingValue`** で切り替える。

| 帯 | 方針 |
|----|------|
| **★9〜10** | **熱量・ねじれフック許容**。催眠は `docs/真催眠音声執筆ガイド.md` §2 既定／特例。同人は `summary` の **`--その〇〇へ、`** 等（`src/content/記事/_同人音声執筆ガイド2.md`）。 |
| **★8 以下** | **構成説明型を標準**。見本：**`src/content/レビュー/futarigake-saimin-dry-iki-support/index.md`**（誘導の並び・区間・終端が読める説明。**不可逆警告や三段脳ハックを義務にしない**）。同人も同趣旨。 |

## 5. ★10 とベンチマーク（インフレ防止）

- **10** は「欠点がほとんど言いにくい」と言えるときだけ。**迷ったら ★9 止め**や本文での減点理由を優先してよい。
- **総合★10 が複数あってよい**が、**売っている約束（コンセプト）が異なるレーン同士**での話。**無関係なジャンルを★だけで横並びにしない。**
- **サイト内ベンチマークの参照例（あくまで例）**  
  - 王道・長尺深化：`unknown-hypno-daijobu-koe-ni-yudanete`  
  - ふたりがけ・情緒・幸福系オーガズム：`futarigake-saimin-love-happy-orgasm`（別コンセプトの厚み：`futarigake-saimin-melty-orgasm`）
- **低評価側の比較アンカー（完成度比較の下限）**  
  - 催眠としての深さが薄く、着地の回収が弱いときの基準：`saimin-shinri-test-dame-iwakareru`（総合★3）  
  - 新規採点時は、**「この作品は★3アンカーよりどこが明確に上か／★10アンカーよりどこが明確に届かないか」**を最低1つずつ `notes` に書く（完成度比較を固定するため）。

詳細は `docs/レビュー三軸評価定義.md` の「10点満点の見取り」。

## 6. データと本文の役割分担

| 置き場 | 役割 |
|--------|------|
| **`src/content/レビュー/<slug>/index.md`** | 読者向け。**略号（C-0 等）は出さない**。根拠・体験の言語化。 |
| **`src/content/レビュー/<slug>/_分析データ.json`** | **三軸の数値**（`scores.*`）、**採点メモ・細目・例外理由**（`notes`）。グラフは `review_triangle.png` 用に三数値と整合させる。 |
| **`review_triangle.png`** | `scripts/generate_review_triangle.py <slug>` で生成。 |

スキーマ：`docs/schemas/review-analysis.v1.schema.json`。

## 7. レビュー1本を仕上げる手順（編集・管理人向け）

### フェーズ A：準備

1. **フォルダ作成**：`src/content/レビュー/<slug>/`（slug は URL と一致する ASCII）。
2. **催眠音声（標準）** … ガワは `npm run review:create-genkami` または Gemini 実行で自動生成。**本文初稿は手書きしない**（`docs/真催眠音声執筆ガイド.md` §1（補・本文執筆は Gemini AI））。
3. **正本で体裁を合わせる（催眠・B 型）**：  
   - **見出し並び・新規の標準：** **`asmr-saimin-aman-toro-lip/index.md`**（甘とろ B 型）  
   - 長尺・引用分量の参考：**`unknown-hypno-daijobu-koe-ni-yudanete/index.md`**（A 型要素は B 型へ移行時に削る）  
   詳細は **`docs/真催眠音声執筆ガイド.md`**。

### フェーズ B：事実・素材

4. **解析パイプライン**（解析フォルダあり）… `docs/真催眠音声執筆ガイド.md` §1（補・解析パイプライン）の 3 コマンド。
5. **Gemini 初稿（催眠・必須）** … `scripts/gemini-hypnosis-review/auto_review.py`（採点3＋本文1→`index.md`）。`.env` に `GEMINI_API_KEY`。
6. **価格一覧** … DLsite のときは `data/products.json` ＋ **`npm run update-price:one RJ…`**。
7. **画像** … カバー・心拍 JPG は **`/content/reviews/<slug>/...`**。**日本語フォルダを URL に含めない**。

### フェーズ C：採点と整合

8. **`_分析データ.json`** … Gemini 出力を起点に、**トランスありき**で最終確定。`notes` に判断メモ。
9. **レーダー画像** … `py -3 scripts/generate_review_triangle.py <slug>`。
10. **`index.md` 校正** … 三軸・総合★・絶頂行・B 型見出しが本書と一致。**B 型では `グラフ評価内訳` なし**（A 型レガシーのみ §3g）。

### フェーズ D：自動補助（任意）

11. 解析フォルダに **`*_waveform.csv` と `.srt`** がある場合、`scripts/analyze_review_auto.py` で `derived_metrics.json` 等を生成できる（投稿完了バッチは `scripts/run_posted_complete_batch.py` でフォルダ対応を管理）。

### フェーズ E：ビルド前

12. **`npm run sync:content-assets`** … `src/content/レビュー/` 配下の非 Markdown を `public/content/reviews/` にミラーする。
13. **`npm run build`**（または CI）で確認。

## 8. 最終チェックリスト（要点だけ）

- [ ] トランスが低いのに快楽・満足だけ突出していない（例外なら `notes` に明示）。
- [ ] `index.md` の三軸・総合と `_分析データ.json`・三角グラフが一致。
- [ ] `## どんな人におすすめか` が点数の免罪符になっていない。
- [ ] （催眠レビュー・**新規または全面改稿**）`## どんな人におすすめか` が **`docs/真催眠音声執筆ガイド.md` §2** の **おすすめ3・合わない2・太字ラベル＋段落** に沿っているか。
- [ ] フリートーク・メイキングのみのトラックで三軸を上下させていない。
- [ ] **総合が★7以下**のとき、`## 作品感想` に「**どうすればもっと良くなるか**」の個人的アドバイスを**1文**入れた（制作・構成・誘導手順など具体的に）。
- [ ] `## 作品感想`（または `### 作品感想`）の**先頭**に **「みなさんお疲れ様です。管理人です(__)」** があり、**複数段落**で体感・余韻が書けている（短文の羅列や箇条書きだけにしていない）。
- [ ] 文体・括弧・グラフ欄の細則：`review-prose-voice.mdc`、`review-graph-no-boilerplate.mdc` と矛盾しない。
- [ ] 読者向け本文で **導線／レール比喩／音響設計** などビジネス・Web調の語を連発していない（`review-prose-voice.mdc`・`docs/真催眠音声執筆ガイド.md` §5）。グラフ軸ラベル「快感設計」等は可。
- [ ] 「挟みやすい」など**目的語のない便利語**だけで段落や実用メモを終えていない（`review-prose-voice.mdc`・`docs/真催眠音声執筆ガイド.md` §3e 項8）。
- [ ] **「主菜」**比喩で構成や嗜好を言っていない（`review-prose-voice.mdc`、`docs/真催眠音声執筆ガイド.md` §3e 項9）。
- [ ] **語感先行の言い回し**（例：「いきなり尖らず」）で進行を説明していない（`review-prose-voice.mdc`、`docs/真催眠音声執筆ガイド.md` §3e 項10）。
- [ ] **`グラフ評価内訳`** が **§3g** に沿っているか（六段落とも2文・深さ標本模倣・技法名＋日常語・2文目は進行動詞・60〜95字・禁止語尾・語の重複なし）。見本：`kuchikou-saimin-count-trip-nouiki`。`review-prose-voice.mdc`・`review-graph-no-boilerplate.mdc` と矛盾しないか。
