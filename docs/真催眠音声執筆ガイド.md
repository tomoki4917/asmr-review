# 真催眠音声執筆ガイド

**正本との関係:** 本書は `src/content/記事/_最強サンプルレビュー執筆ガイド.md` および `.cursor/rules/review-prose-voice.mdc` と**あわせて使う**、催眠レビュー用の**補助正本**です。特に **ルート B（高密度パース・構造総括）** の手順・体裁を定めます。**2026-05 以降、当ルートの標本は `futarigake-saimin-coming-orgasm`（カミング標本）**とする。ラブハピ基準の「一式」と二層になる箇所は、**本書のカミング標本節を優先**し、ルート A との**併記**で読み分けてください。**ユーザー添削で確定した運用の要約は §9**、詳細規定への入口は **§1（補・続）の一覧表**。

---

## 1. 目的

- 読者の**理性を論理でほどき**、**本能側の「聴きたい」**に接続する。
- 「作品が何をしているか」だけでなく、**聴き手の身体に何が起きうるか**を文章に織り込み、再現性のイメージを持たせる。
- ただし**医学診断・効果保証**は書かない。強い口調は**体験の宣告**として書き、必要なら**個人差**を一言で添えて誤解を避ける。

## 1（補）. カミング標本に準拠する記事グリッド（ルート B）

**標本ファイル:** `src/content/レビュー/futarigake-saimin-coming-orgasm/index.md`  
**準拠更新の実装例:** `src/content/レビュー/kyoku-mugen-zekkyou-count-chikuni/index.md`・`src/content/レビュー/futarigake-saimin-melty-orgasm/index.md`・`src/content/レビュー/kuchikou-saimin-count-trip-nouiki/index.md`

**再発防止メモ:** ルート B は本文の論旨だけでなく**見出し番号・YAML の title・グラフ内訳の段組・おすすめの改行**まで標本とずれると、読者が記事間で体裁を比較したときに信頼を損なう。新規執筆後またはガイド改訂後は、**セクション 1（補）のチェックを別ファイルとして再走査**し、既存記事はカミング標本へ寄せ直す。**ユーザー添削で方針が確定した項目**（例：§2・おすすめ／合わない 項6 のとおりおすすめに解除を載せない）は、該当レビュー本文の修正と**同時に**本書・`_最強サンプルレビュー執筆ガイド.md`・`.cursor/rules/review-prose-voice.mdc` へ反映し、類似表現を grep で洗い出す。

### 1（補・解析パイプライン）ユーザー解析フォルダを受け取ったあとの計測（記事執筆前・必須）

**対象:** ユーザーが毎回渡す**解析フォルダ**（`.mp3`・`.srt`・`*_waveform.csv`・文字起こし `json`／`txt` 等。音声はリポジトリに入れない運用のまま）。

**エージェントは `index.md` の本文執筆に入る前に、次の順で実行する**（同人・催眠の別を問わない。手順1は **`.mp3` がフォルダに含まれるとき必須**。MP3 が無い案件のみスキップ可）。

1. **`py -3 scripts/analyze_mp3_immersive_metrics.py "<解析フォルダの絶対パス>" <slug>`**  
   各 MP3 を約 **0.1 秒**フレームで読み、`src/content/レビュー/<slug>/spatial_spectral.auto.json` を生成する。内容は**左右チャンネル RMS から得た定位の材料**（`(L-R)/(L+R)` の平均絶対値・標準偏差）、**スペクトル重心**、**4 kHz 以上のエネルギー比**（気声・息・歯擦音など**高域が相対的に多い区間の目安**。囁きの自動断定ではない）のトラック別・集約値。  
   **依存:** `py -3 -m pip install -r scripts/requirements-audio.txt`。MP3 デコードには **ffmpeg 等が PATH** に必要な環境がある。
2. **`py -3 scripts/import-review-analysis.py "<解析フォルダ>" <slug>`** … 音声以外を `analysis/` へ（既存ルールどおり）。
3. **`py -3 scripts/analyze_review_auto.py "<解析フォルダ>" <slug>`** … `derived_metrics.json`・`sections.auto.json`・`events.auto.json` を生成／更新。**手順1が済んで `spatial_spectral.auto.json` が slug 直下にあるとき**、`derived_metrics.json` の **`immersive_audio_mp3`** に集約が取り込まれる。`_分析データ.json` が既にあれば、既定で **`notes` に【自動補助根拠】**へ定位・高域比の要約行が付く（`--no-update-notes` で抑止可）。

**執筆への使い方（採点との関係）:** 上記は **`docs/レビュー三軸評価定義.md` に照らす材料**であり、数値をそのまま星に換算しない。特に**トランス度**は台本・暗示が主軸のとき、音響指標は**補助根拠**に留める。本文・`summary` に**スクリプト名・生 JSON・列名**を書かない（§3b「解析メタ発言の禁止」と同旨。`_分析データ.json` の `notes` は執筆者向け）。

### 1（補・DLsite 税込価格）一覧・詳細の価格ブロック（再発防止）

**症状:** `index.md` に **`dlsiteProductId`**（`RJ…`）があるのに、トップ一覧のカードに **¥ が出ず**、詳細の **「DLsite 価格」が空／未取得**になる。

**原因:** 実装の正本は **`data/products.json`** である。**フロントマターに `dlsiteProductId` を書いただけでは価格は描画されない**。同一 **`id`** の行があり、**`current_price` が正の整数**として取り込まれている必要がある（`src/lib/types.ts`・`DlsitePricePanel.tsx` と同旨）。

**新規レビュー・`dlsiteProductId` を付けた／変えたときの必須（公開前）:**

1. **`data/products.json`** に **`id`** と **`url`**（`https://www.dlsite.com/maniax/work/=/product_id/RJ….html`）を **1 件追加**（他行と同じ URL 形式に揃える）。
2. リポジトリ直下で **`npm run update-price:one RJ…`** を実行し、当該行の **`current_price`・`original_price` 等が埋まる**ことを確認する（全作品を再取得したくないときは **`npm run update-prices` 全件ではなく** これを使う）。
3. **`http://localhost:3000/reviews/<slug>/`** で **DLsite 価格パネル**が表示されること、トップで **¥** が並ぶことを確認する。

**コミット前の機械チェック（エージェント）:** `dlsiteProductId` を新設・変更した `index.md` ごとに、`data/products.json` を **`rg` / grep で同一 `RJ` が存在する**まで完了としない（`.cursor/rules/review-content-workflow.mdc` の手順 2 と整合）。

ルート B の記事は、少なくとも次の**見た目と情報の並び**をカミング標本に揃える（中身は作品ごとに差し替える）。

1. **`title`** … サイト用に `【レビュー】` を前置してよい（`itemName` は販売ページの商品名どおりとし、`title` だけレビュー用に変える）。
2. **`## 作品概要` → `### 基本情報`** … 一行で読める **`主題:`** を置いてよい（種類・**声優**（名前のみ・括弧で DLsite／RJ を付けない）に続く bullets）。
3. **`### パートの長さ`** … 見出しは **`### パートの長さ`** の固定とし、本文は **時間情報だけ**で組む。先頭に **`**合計約 ...**`** を置き、その下に各パートの時間を箇条書きで並べる。**各項目はパートの正式名称を必ず含め**、**`06` や `05` だけ＋時間**のように**番号単独で区間を指す書き方は避ける**（販売表記が番号起点のときは **`01 催眠誘導1`** のように**番号に続けてパート名を同居**させる。名称のみで足りるときは **`### パートの長さ`** でも**番号なし**でよい）。**出典名（販売ページ／info.txt／analysis／字幕終端／`derived_metrics.json` など）は本文に書かない**。公式の時間表記がある作品はその値を優先し、公式に時間がない作品のみ解析データを内部参照して補完する（ただし本文には参照元を書かない）。
4. **`## どんな人におすすめか`** … 各項目は **太字で属性を書いたうえで改行**し、理由は**次行以降の段落**で書く（同一行に「…」で詰め込まない）。内容の細則はセクション 2 内の「おすすめ／合わない」を参照。
5. **`## 総合評価` の `グラフ評価内訳`** … 各軸を **`軸名 整数（サブ項目A / サブ項目B）`** とし、その直下に **太字小見出しが二つ続き、それぞれに段落**を置く。**軸行の括弧内**は、読者が記事間で体裁を照合できるよう、次の**語順・スラッシュ・ラベル語を固定**する（**変えるのは各軸の主点数とサブ点数だけ**。括弧内の **入り／深さ／快感設計／ピーク回収／着地／余韻** の六語および間のスペース・スラッシュ表記は変えない）。
  
  **追記（2026-05）:** `グラフ評価内訳` は誘導・暗示の構成比テーブルより前に出るため、本文で **「誘導比 3.8」「暗示比 2.1」** のような構成比の生数値参照をしない。ここは **機能語（命令主導・反復維持・語彙トリガー等）で定性的に説明**し、詳細数値は `本作の誘導・暗示解析詳細` 以降で扱う。

   **固定見本（カミング標本の数値どおりそのまま・文言変更禁止）:**

   - **トランス度 9（入り 9 / 深さ 8）**
   - **快楽度 9（快感設計 9 / ピーク回収 9）**
   - **満足度 9（着地 9 / 余韻 9）**

   実装では上記の **9** を作品ごとの整数に差し替える。**直下の太字小見出し**は、まず **`入り`・`深さ`・`快感設計`・`ピーク回収`・`着地`・`余韻`** を核にし、必要なら **全角括弧で本作固有の一言**を添える（例：`futarigake-saimin-coming-orgasm` の **入り（導入）**／**深さ（持続）**）。サブ見出しの核語を別語へ全面置換して軸行とずらさないこと。

   **グラフ本文の文体テンプレ（2026-05 追記）**  
   三軸の本文は、感想語より**機能語**を優先し、次の順で組む。  
   **観測事実（どの区間で何が起きるか）→ 機能（何が更新・維持・遷移するか）→ 設計結論（何を抑止・回避・保護するか）**。  
   推奨語彙は **コンテキスト固定／状態遷移／入力強度／持続性／積層／沈静／再統合**。  
   非推奨は **「とろとろ」「長尺」** などの印象語を根拠語として多用する書き方。必要ならパート名・尺表記に限定する。  
   見本は `futarigake-saimin-melty-orgasm/index.md` の `グラフ評価内訳`（2026-05 改稿）。
6. **`## パート別解析`** … 見出しは **`### パート名`** を**主**とする（例：**`### 覚醒`**、**`### 催眠誘導1`**）。**`### 006` のように番号だけの見出しは禁止**。カミング標本の **`### 001 最初`** のように**番号＋固有名が一体**の見出しは互換のため残ってもよいが、**新規・改稿ではパート名を先に**置く形（**`### 覚醒`** 等）へ寄せる。**三位にそろえる**（`001` 形式）は、上記と両立するときに限り推奨する（既存記事が `01` のみのときはレビュー内で統一されていればそのままでよい）。直下に引用、`**解析:**`、`**身体の反応:**`（セクション 3b）。引用はパートの**核**のみとし、**解析・身体はパート全体の尺と設計**を書く（§3b）。
7. **`## 総評：本作品の構造的結論`** … **標準三柱**にそろえる（【設計の論理的総括】【物理的干渉の機序】【結論】）。標本ファイルもこの見出し語で統一する。「機序」は一点のハックに絞る（セクション 4b）。
8. **装飾** … `パート別解析` と `総評` のあいだに **水平線 `---` は入れない**（標本どおり h2 が連続する）。
9. **`### 聴取時の身体反応（心拍）`（任意・データがあるときのみ）** … **ルート B では `## 作品概要` 内には置かない。**Polar H10 等の波形があるときは **`## 総合評価` のブロック末尾**——`**グラフ評価内訳**` と「以上から総合 …」の**直後**、かつ次の **`## `（例：`パート別解析`）の手前**——に **`### 聴取時の身体反応（心拍）`** を置く（サイトでは「総合評価」見出しカードの続きとしてその直下に表示される）。導入の **A／B 型**、画像 **`polar_h10_heart_rate_session.jpg`**、alt、波形読みの細則は **`src/content/記事/_最強サンプルレビュー執筆ガイド.md`** の「心拍導入文の二系統」「聴取時の身体反応（心拍）— 標準フォーマット」に従う。**画像がない作品では省略**する。

### 1（補・クイック）. 2モード表示（クイック解析／作品詳細解析）標準

本節は、レビュー上部で **「1分で判断」** を先に読ませる運用を正式化する。  
UI 文言・並び・語彙レベルを固定し、作品ごとの差分は値のみ差し替える。

1. **配置と切替（固定）**
   - 価格ブロック（DLsite 価格）直下に **記事モード切替**を置く。
   - ボタン文言は次を正とする。  
     - `1分で判断！クイック解析`  
     - `しっかり見たい人向け！作品詳細解析`
   - **クイック選択中は詳細本文を閉じる**（非表示）。
   - **詳細選択中のみ** OUTLINE と本文を表示する。

2. **クイック見出し（固定）**
   - 見出しは `⚡️ 1分で判断！クイック解析`。
   - 冒頭 2 行は次の型で固定。  
     - `★ 総合スコア：x.x / 10`  
     - `一言で： 「作品固有の体験を一文で断定」`
   - **回数表示（固定）** … `★ 総合スコア` の**直下**に、絶頂回数を次の表記で置く。  
     - `ドライx回 / ウェットy回`  
     - どちらかしか無い作品は存在する側のみ表示（例：`ドライ3回`）。
    - **回数の数え方（再発防止）** … `ドライx回` は「導入・予告・焦らしの回数」ではなく、**明確な到達回収（行く／果てる等のピーク確定）**を数える。先走り・未到達・示唆のみは回数に含めない。
   - `一言で` はテンプレの使い回しを避け、**当該作品の summary / 構造 / 主体験**に合わせて毎回書き下ろす。

3. **クイックスペック表（順序固定）**
   - `誘導タイプ`
   - `声優`
   - `テンポ`
   - `主要フェチ`
   - `性癖タイプ`
   - `おすすめ催眠Lv`
   - `収録時間`

4. **語彙と書式（クイック向け）**
   - **誘導タイプ** … 3 つまで併記可（`A / B / C`）。  
     例：`洗脳系 / 服従・支配系 / 反復刷り込み系`
   - **声優** … **DLsite 作品ページの「CV:」に書かれている名前を確認したうえで、レビュー本文では名前だけを書く**（敬称略は販売ページに合わせる）。複数名が列挙されていれば **全員** を書く。  
     例：`みもりあいの`  
     **本文では付けない:** `（DLsite 作品ページ「CV:」表記・RJxxxxxx）` のような **出典・商品IDの括弧付記**。根拠は執筆時に販売ページで確認すればよく、`dlsiteProductId` と `quickGuideBySlug` が別途ある。  
     **禁止:** 「複数」「マルチボイス」「（バイノーラル）だけ」など **キャスト名を省略したプレースホルダ**。マルチ入力作品でも、公式が1名のみ記載なら **1名だけ** で正しい。
   - サイトに体験版・音声サンプルURLがある作品は、**声優の横に** `音声サンプルはこちら` リンクを表示する。
   - **テンポ** … `速度 / 型（説明）` で書く。  
     例：`ややゆっくり / 断続系（間が多い）`
  - **おすすめ催眠Lv** … **`区分名（内訳）以上の方`** の形を正とする（末尾の **`以上の方`** は必須）。
    例：`初心者（浅いトランス＋暗示受容が可能）以上の方`
   - **収録時間（`quickGuideBySlug[].recording`）** … **人間可読な尺**（例：約1時間12分29秒）に、必要なら **トラック数・通し／分割・字幕終端**など**買い判断に使う平易な情報**だけを短く足す。**禁止:** 「単一ロング」など内部ラベルと **`duration_sec` の生値**を括弧で並べること（例：`（単一ロング・duration_sec 4348.861）`）。生の秒値は **`### パートの長さ`**・**`_分析データ.json`**・**`derived_metrics.json`** 側に寄せる。

5. **性癖タイプ（選択肢固定）**
   - `M推奨`
   - `ノーマル`
   - `ドM`
   - `S`
   - `ドS`

6. **レベル区分名（クイック表示用）**
   - Lv1: `入門前`
   - Lv2: `初心者`
   - Lv3: `初中級`
   - Lv4: `中級`
   - Lv5: `上級`

7. **おすすめ／合わない（固定見出し）**
   - `【こんな人におすすめ】`
   - `【合わない可能性がある人】`
   - 各項目は 1 行目で条件を言い切り、理由は短文で補う（冗長な分析文は詳細側へ回す）。
   - **クイックのおすすめで「長尺だから」「通し再生だから」のような汎用条件を主軸にしない。** 作品固有の刺さり方（例：往復深化、同一化語り、分岐運用、トリガー語の癖）を優先し、尺情報は `収録時間` または `### パートの長さ` へ分離する。

8. **価格 CTA（クイック末尾）**
   - 文言は `➡ DLsiteで作品をチェックする（...）` を正とする。
   - セール中は割引率を明示し、視認できる強調（色・バッジ）を付ける。
9. **詳細解析の冒頭方針（2026-05-09 追記）**
   - `しっかり見たい人向け！作品詳細解析` 側でも、冒頭段落・`summary`・`## 解析結論` は「長尺だから」「濃密だから」のような汎用語で済ませない。
   - 必ず **作品特有の強み**（例：往復深化の型、同一化語り、経路切替、分岐運用、特定トリガー語）を先に提示し、一般的な尺情報は `### パートの長さ` に分離する。

10. **反映範囲（実装運用・2026-05-08 追記）**

**フック短文型の語尾テンプレ（2026-05 追記）** … **★9〜10 のみ**。アンノウン標本に寄せる場合、`summary` は「読者の欲求（〜したい）→本作の応答（構造の事実）」を**一文**でつなぐ。語尾は **「〜になっています」「〜で続きます」「〜として読めます」** など、**観測可能な構造の記述**で閉じる。**「受け止めにきます」「連れていきます」**のような擬人化・決め台詞調は避ける。  
（例）「〜したい——そんな欲張りへ、双子の左右定位による聴覚同期が終幕まで持続する設計になっています。」

**過去記事との体裁合わせ（YAML・見出し間・2026-05 追記）** … ルート B の新規・改稿では、既存催眠レビューと**カード周りの見た目**を揃える。**フロントマター**は `slug`・`title`・`summary`・`tags`・評点・`itemName`・`itemDescription`・日付・画像・`affiliateLinks` の**ブロックあいだに空行1行**（見本：`futarigake-saimin-coming-orgasm`・`kyoku-mugen-zekkyou-count-chikuni`・`jinsei-senpai-koi-dorei-mind-control`）。`summary` が短文でも **「『欲求』『欲求』」--その〇〇へ、** の **ダッシュで橋渡し**する型は過去記事で標準的。**`tags`** は **催眠音声を先頭**、**バイノーラルは末尾**が多い（一覧での読み順）。本文では **`## 作品名` の直後に `---` を1行入れ**、`## 作品概要` へ進む（同上見本）。

1. **ターゲット（共感と看破）**  
   言語化しにくい執着・焦燥（例:「イかなければ」への縛り）を**短く言い当てる**。ここで終わらず、作品がその願望を**抽象的なイメージだけで済ませず**、鑑賞のなかで**どう処理していくか**（実行のイメージが立つ語り）へつなげる。
2. **体験（生理的変化）**  
   定位・密度・リップ・呼吸同期など**音の組み立て**が、**どのように注意を奪い**、**どんな無力な快感**を立てうるかを、**宣告調**で書く（説明書の箇条書きにしない）。作品がカウント・禁止・短文トリガーに依存させるタイプなら、**数字や合図が進むほど身体側が先行する**など、依存的な聴き心地を**断言できる範囲**で明示してよい（結果保証にはしない）。
3. **警告（不可逆性）**  
   聴いたあとに**これまでの自己処理が空虚に感じる**など、**中毒性／手放しの難しさ**を一文で提示し、読者に**選択の重み**を渡す（購入の免罪符＝「知っていた」ではなく**覚悟の共有**に留める）。途中中断で未完了感が残る構成なら、その**必要な通し区間**（例：ループだけで止めず脱出〜覚醒まで）をここまたは直後の段落で書く。

**4. タイトル・販売語の独自解釈（断定）**  
「魔改造」「無限」「カウントトリップ」など、読者がリピートや購入判断に使う語がタイトルやパッケージにあるときは、**原則** `summary` の**いずれかの段落で**、**レビュアーの言葉で何を指すかを断定する**。**§2 冒頭の「フック短文」特例**では、`summary` ではなく **`## 作品概要`・`## 総合評価`・パート別** など本文で断定してよい。例としては次のような粒度である（作品ごとに置き換える）。

- **快感の起点がどこからどこへ書き換わるか**（例：性器中心から乳首中心へ）
- **どの音・どの数字・どの合図へ条件づけが張られるか**（例：「ゼロ」の音声に対して反射が先行する）
- **それが身体的プロセスとして何を意味するか**を、医学ではなく**鑑賞・体感の語彙で一段だけ言い切る**（例：脳内の快感地図を描き直す、など）

読者はこの断定を信じて繰り返し聴く前提があるため、**曖昧な煽りのまま放置しない**こと。

**5. 語彙：抽象メタファの抑制**  
「装置」のように、読み手が**因果や手順を追尾しにくい**語は**使わない**。代わりに **実行手順**・**結びつけ**・**条件づけ**・**上書き**・**完了条件** など、鑑賞中に何が起きるかが想像できる語を優先する。「システム」は作品固有の語としてパッケージに含まれる場合を除き、**多用しない**。

**`summary` 冒頭だけの追加（集合語・業務調の抑制・再発防止）** … 読者の願いを言い当てた直後に、本作を **「実行手順の束」** **「〜を束ねた一式」** など、**集合・効率・マニュアル**を連想させる語だけで括ると、論旨は正しくても**無機質・冷たく**読まれやすい（**束**は特に業務調のノイズになりやすい）。**「〜という層へ、本作は〜として応える」**だけだとターゲティング広告のような距離感にもなる。代わりに、**諦めたくない感情・願い**を明示したうえで、作品側は **環境から丁寧に積み上げる「実行手順」として応えていく** **〜していってしまう** など、**処理の見通しと寄り添い**が両立する言い回しを優先する。**実行手順**という語自体は有用だが、`summary` の**最初の段落**では **「束」「一式に収める」へのすぐ結びつけ**を避ける。見本：`unknown-hypno-daijobu-koe-ni-yudanete/index.md` の `summary` 先頭段落。

### `## どんな人におすすめか`（おすすめ／合わない）

**狙い:** 読者が自分を写すだけでなく、**本作のどの設計と自分が噛み合うか（／噛み合わないか）** を一秒で把握できるようにする。

1. **属性と理由をセットにする（催眠で「何が得られるか」を明示）**  
   **`太字で読者属性`** を書いたら**改行**し、続けて **本作固有の因果** を段落で書く。カミング標本どおり、同一行に「…」だけで済ませない。  
   おすすめ本文では、読後に読み手が即判断できるよう、**本作の強み**・**作品特有のトランス誘導の癖**・**快楽の与え方／感じ方**・**シチュエーションで得られる体験**のうち、最低2軸を必ず入れる。
2. **おすすめ側は「本作固有の供給価値」で書く**  
   例として、定位の癖、反復語のトリガー設計、返答プロトコルの有無、ピーク運用の型、ロールプレイの拘束条件など、**この作品でしか受け取れない催眠体験**へ結ぶ。**パート解析や本文と矛盾しない語**を使う（トラック名・パート名は実際の構成に合わせる）。
3. **合わない側は「除外条件＋ズレのメカニズム」**  
   例として、音声のみでは身体側の感度が追いつかず体感が乖離する（そのときの前提としてセルフケア等）、特定パートで日常入力を快感側へ再解釈する暗示があり持ち越しが気になる、など。**どのような約束が合わない層と衝突するか**まで書く。
4. **強い断定語と効果保証の線引き**  
   「最大化」「支障がない」「可能です」などは読み手によって**結果保証**に読まれうる。使う場合は同項目内または近傍で **個人差・前提・しやすさ** を補い、医学的主張にならないようにする（セクション 1 の目的・正本と整合）。
5. **語彙**  
   「手続き」「実行手順」「収束」などはよい。**装置**は避ける（セクション 2 の語彙方針どおり）。読者が「通しで手順として締めたい」と分かるなら **プログラム** も一案だが、空虚なメタファにしないこと。
6. **おすすめに「通し再生前提」「解除される」を載せない（再発防止）**  
   催眠音声では**通しで聴く運用**や**暗示解除・覚醒まで付く構成**が前提に近く、「最後まで聴ける」「解除があるからおすすめ」は差別化にならない。**解除まわりの文言の巧拙・後催眠の趣旨・ループとの対比・終わり方のトーン**は、`summary` の警告、`## 総合評価`・グラフの着地／余韻・`**満足度**` の説明、`## パート別解析` の解除パート、または**合わない側**（後催眠の持ち越しが気になる層など）で書く。  
   おすすめの属性見出しは「だからこの作品が届く」と読めるよう、**本作特有の誘導癖・快感設計・シチュエーションで得られるもの**へ結ぶ。
7. **比率** … **おすすめ 3 項目・合わない側 2 項目（3:2）** を原則とする（詳細・サイト体裁は `_最強サンプルレビュー執筆ガイド.md` §3 項3）。項目を削るなど特例にするときは `_分析データ.json` の `notes` に理由を残す。
8. **語彙（機能語優先・再発防止）**  
   おすすめ／合わないの説明段落は、**設計思想・持続性・状態遷移・同期・収束**などの機能語で書く。**「とろとろ」「長尺」**のような感覚語・尺語を主語にせず、必要なら `### パートの長さ` でのみ尺を示す。目的は「何が機能し、どの層に噛み合うか」を一読で判定できる密度にそろえること。
9. **見出しの長さ（2026-05 追記）**  
   `おすすめしたい方`／`合わない可能性がある方` の各箇条書き見出しは、**1フレーズで言い切る短さ**を標準にする。目安は**20文字前後**（必要なら超えてよいが、30文字超の連続は避ける）。詳細条件は本文段落で説明し、見出しはスキャン用のラベルとして機能させる。
10. **見出しと本文の役割分離（2026-05 追記）**  
   見出しは「誰に合うか／合わないか」を即時判定するラベルに徹し、本文段落で **機序・入力条件・認知負荷・状態遷移・残存リスク** を説明する。  
   目安は **見出し＝平易／短文、本文＝専門／論理**。この分離により、初見読者の可読性とレビューとしての分析密度を同時に満たす。
11. **快楽系見出しの平易化（2026-05 追記）**  
   快楽の感じ方に関する見出しは、専門語や抽象語を前面に出さず、**体感が一読で分かる日本語**を優先する。  
   例：`語感の強い支配語彙に没入できる方` より `支配される感覚で快感を高めたい方` を優先。詳細な誘導機序・語彙設計は本文段落で補う。

**参照例:** `futarigake-saimin-coming-orgasm/index.md`・`kyoku-mugen-zekkyou-count-chikuni/index.md` の `## どんな人におすすめか`

## 3. パート解説／パート別解析

### ルートの選び方（重要）

| ルート | 見出し | 向き先の例 |
|--------|--------|------------|
| **標準（ラブハピ基準）** | `## パート解説` | 販売コピー寄りの総論・手記的温度を **`## 作品像` → `## パート解説` → `## 作品感想`** で積む。 |
| **構造総括型（カミング標本）** | `## パート別解析` | **`## 作品像` を置かず**、総合評価のあと**いきなりパート別**。末尾は **`## 総評：本作品の構造的結論`**（下記 §4b）。 |

サイトでは `## パート解説` と `## パート別解析` は**同じ見出しスタイル**になる。名称は執筆上の宣言として使い分けてよい。

### 3a. パートブロックの基本方針（カミング標本＝本節フル適用）

1. **「解説」ではなく「解析」**  
   台本のあらすじにとどめず、**定位・呼吸・リズム・ミキシング**など収録から言い切れる**音響的事実**が、リスナーの注意と判断をどう再配分するかを**論理的に解体**する。
2. **因果関係の明確化**  
   **`〇〇という演出（音響的事実）` → `その結果、処理／判断がどう諦めざるを得なくなるか（論理のステップ）`** の順で書く。飛躍があるときは、中間ステップを一文足す。
3. **文体の統一（解析ブロック内）**  
   「私には〜と感じました」などの聞き手主観は**使わず**、解析調を基本とする。**読みやすさ優先**の案件では §3e に沿って **です／ます体**でもよい（高密度パース・催眠向けにありがち）。**一人称の体験記は `## 作品感想` ルートにのみ**置く（§4a）。**ルート B のパート別**では、論理は保ちつつ **〜ていく／〜してしまう／〜ですね／〜てくれる** などで**温度**を足してよい（§3e 項5）。**総評（§4b）**は引き続き三人称・硬めの締めでよい。
4. **身体の反応の記載**  
   各パートの末尾に、聴取時に観測できた事実を **`身体の反応：`** で**一至二文**に収める（医学診断・効果保証は書かない）。読みやすさ優先なら**体言止め・名詞句**でもよい。  
   なお、**ピーク／絶頂を扱うパート**では、快楽相（収縮・熱感・放出感・脱力移行など）を観測語で書く。  
   **ドライ／ウェットの明示は、台本・分析データ・既存評価で確認できる場合のみ**行う。確認できない場合は「ピーク局面」「絶頂局面」などの中立表現を使い、推定で断定しない。

### 3b. 構成フォーマット（パート単位・カミング標本）

パート見出しの直下に**引用**（台本の根拠＝**演出の核**。別見出しや要約ラベルは置かない）を置き、そのあと **`**解析:**` → `**身体の反応:**`** を**この順で**並べる。

```markdown
### パート名（例：覚醒、催眠誘導1）

> （該当台本の引用。必要なら複数行）

**解析:** （例：引用どおり左右の情報が詰め込まれ、定位の隙間から「保留」が削られる。その結果、理性側のブレーキより先にリズム側へ注意が固定されるという設計である。）

**身体の反応:** （例：波が返るたびに腰が反応し、思考より先に「次」を肯定させられる。）
```

**カミング標本との分担（再発防止）** … `futarigake-saimin-coming-orgasm` に合わせる。**自律神経や回路レベルの説明**（例：副交感神経を優位に導く、強制委譲など）は **`**解析:**` 直下の段落**に書く。**`**身体の反応:**` 直下の段落**は**一至二文**で、観測しやすい**筋・呼吸・固定の困難さ・熱感・痙攣・視界・重心**などに限定する。「安心」「期待」「想像が立ち上がる」だけで**身体の反応を済ませない**（情動・認知は必要なら解析側で一言触れ、観測句は肉体側へ落とす）。

**ロジカル・レポート調（実体験ベース・推奨）** … 聴取ログに近い密度で書く案件では、パート別の `**解析:**` と `**身体の反応:**` を次のように整える。（1）`**身体の反応:**` … 主観の感想や詩に寄せた描写にせず、実際に起きた変化を**観測可能な現象**として言い切る。「〜になります」「〜します」「〜してしまいます」「〜に達してしまいます」などの**断定調**を軸にし、「予測されます」「〜しうる」「かもしれません」をレポートの主軸からは外す（効果保証・医学診断にはしない前提で、解析者としての実感ある報告調）。（2）`**解析:**` … 設計・因果も同様に「〜になっています」「〜機能する流れになっています」「〜強調されてしまいます」などで組み立て、推測語だけの積み上げにしない。（3）**レール**など製品メタを連想させる比喩で身体や定位を説明しない（読者向け語彙ルールと整合）。**見本:** `unknown-hypno-daijobu-koe-ni-yudanete/index.md` の `## パート別解析`（2026-05 改稿以降）。§3e の温度と両立させてよいが、本調で書くときは**観測の言い切り**を優先する。**`**身体の反応:**`** は §3a の一至二文目安を踏まえつつ、本調では**短文を二〜三文つないで観測を詰める**書き方も可（読みのテンポが死なない範囲で）。

**伝達物質名（任意）** … **ドーパミン・エンドルフィン・オキシトシン**を **`**解析:**` の段落に織り込む**ときは、**物質名を先頭に置き**、括弧内に読み手向けの短文ラベルを付ける。**オキシトシン（親密さ）**・**ドーパミン（期待）**・**エンドルフィン（じんわりした充足）** のような **物質名（ラベル）** を標準とする（専門語が先に立ち、スキャンしやすい）。作品ごとにラベルは変えてよい（例：**ドーパミン（報酬予測）**・**エンドルフィン（脱力）**・**オキシトシン（安心感）**）。**ラベル（物質名）**の逆順（例：期待（ドーパミン））は**用いない**。比喩であり分泌や効果を**断定しない**。**「〜に擬せた」** は読みにくさや添削のノイズになりやすいので**使わない**（再発防止）。`## パート別解析` の冒頭に「比喩です※」のような**全体脚注は置かない**。**`**身体の反応:**` の段落**に**肉体側の観測**を書く（実例：`kyoku-mugen-zekkyou-count-chikuni/index.md`）。

**引用と解析の役割分担（再発防止）** … 引用ブロックはそのパートの**核となる台詞だけ**を示す。**`**解析:**` は引用の逐語説明に終始せず**、そのパート全体の尺・構造・音響設計（どの手続きがどれだけ続くか）を見渡した論旨**を書く。**`**身体の反応:**` も引用に対応する一行だけでなく**、そのパートを通した体感の推移**を一至二文でまとめる。

**正本の `## パート解説`**（引用→解説が主体の記事）では、この **`解析:`／`身体の反応:`** ラベルは**必須ではない**。ただし論理解体が薄くならないよう、**§3a の因果の型**は参照してよい。

**通し1ファイル／非分割音声の区分（重要）** … 音声が実質1本で、mp3ファイル名やトラック番号が機能区分を表さない場合は、**`### パートの長さ` では実際のファイル単位を記載**する（本編／解除など）。  
機能区分（導入／深化／エロパート／解除 など）へ再分割するのは、**`## パート解説`／`## パート別解析` のみ**で行う。見本: `src/content/レビュー/brain-washer/index.md`。

**尺のリード文（再発防止）** … `### パートの長さ` は **時間だけ**を置く。先頭は **`**合計約 ...**`** に固定し、続けて各パートの時間を列挙する。**「単一ロング」等の内部ラベル・`duration_sec` の生値・参照元ファイル名の注記は禁止**。公式時間がない場合は内部で解析値を使って補完してよいが、本文では出典を明示しない。

**解析メタ発言の禁止（再発防止）** … `**解析:**` 本文で **「ここは文字起こし上で〜」** のような、解析手順を説明するメタ前置きは使わない。読者向け本文では、区分や根拠を手順語で語らず、**パート名と観測事実をそのまま因果で記述**する。

**パート番号の本文参照（再発防止）** … **`グラフ評価内訳`**・**`## どんな人におすすめか`**・**総合評価**・パート別の `**解析:**`／`**身体の反応:**`** など、読者向けの**実行文**では、**`06`**・**`05 帯`** のように**トラック番号や桁だけ**で区間を指さない。**`### パートの長さ` に並べた正式パート名**（例：**覚醒**、**耳舐め絶頂エンドレスパート**）で書き切る。尺一覧・見出しで番号を併記する場合も、**本文からの裸参照にしない**（§1（補）項3・§11.7）。

**技法名の括弧**は正本どおり**催眠誘導の手続きに限定**し、状態俗語を括弧のラベルにしない。

**催眠技法語の初出と括弧内説明（ペーシング・ラポール等）** … **ペーシング**・**ラポール**・**アンカリング**・**コンフュージョン** など、読者によっては馴染みが薄い**催眠の手続き名・定型用語**が記事で**はじめて登場するとき**は、その**直後に全角括弧**で**簡易的な説明を一言**入れる（例：ペーシング（声やメトロノームのテンポに、呼吸などを同期させる誘導）、ラポール（抵抗を弱めるための信頼関係づくり））。**同じ記事内の二度目以降**は説明括弧を繰り返さない。**`summary`** にこれらの語を置く場合も初出扱いとするが、原則 **`summary` に技法名を並べない**（§2 の密度優先）。

見出しやグラフ小見出しに技法語が先に出てしまう場合は、(1) 見出し側で別語に置き換える（例：**リズム同期**）、または (2) **直下の最初の本文**でその語を繰り返し **語（説明）** とする、のいずれかで**無説明の初見だけを残さない**。辞典のような長い定義にはしない。

**技法語の適度なちりばめ（推奨・添削メモ）** … 解析や総合評価の段落のなかで、**ペーシング・ラポール・分割法・アンカリング**など**実際に台本が踏んでいる手続き名を、該当する因果の説明へ適所で織り込む**書き方は望ましい。読み手に**専門性**と**再現の手がかり**の両方が伝わりやすくなる。**一方で**、接続詞もなく**用語だけを短文でならべて用語索引にする**書き方とは切り分ける（因果・音響的事実とセットにする）。このくらいの**ちりばめ**であれば積極的に使ってよい。**初出の括弧説明**は §3b どおり。

### 3c. 解析素材との突き合わせ

作業フォルダに同梱した **JSON・VTT・SRT・waveform CSV** など（例：投稿前チェック用の v2 一式）とタイムコード・波形を突き合わせ、**音響的事実を捏造しない**。リポジトリ内の `analysis/` と内容がずれるときは、掲載前にどちらを正とするか決める。

### 3d. 断定の置き場・音響的根拠（解析以外でも共通）

1. **強い断定は「効果保証」ではなく「作品クオリティ評価」へ**  
   「絶対にイける」などの**結果保証**は書かない。代わりに **構成・密度・音の運び**への評価として強気に言い切る（主に **`## 作品感想`**・**`## 総評：…`**・総括）。
2. **`summary`・グラフ本文の語り**と **パート別ブロック** の役割は分ける  
   前者は読後動機やスキャン優先の短文、後者は**理屈の透明度**優先。同じ文言を細分化して貼り付けない。

### 3e. 平易化の優先（添削で効いたこと）

内部機序を**細かく積み上げただけ**の長文化は、スキャンも理解も落ちる。**読者が一読で手順→効果の筋を追える**ことを優先する。

1. **因果を短く並べる** … 「〜により」「〜することで」「〜によって」をはっきり置き、一段飛びを減らす。
2. **専門語にはひと言相当の説明を添える** … 引用符・括弧でよい（例：自律リズムの外部委譲、淡い快感での障壁除去、正のフィードバック）。
3. **解析と身体の反応の分担** … 解析はメカニズム／設計の意図、身体の反応は観測。**同じラベルを両方に重ねない**（副交感優位などはどちらかに寄せる）。
4. **強調記号は要点の短句だけ** … 長文全体を太字にしない（細かい運用は本文制作側で調整）。
5. **論理と温度の両立（再発防止）** … 「〜です」「〜する設計です」だけの**説計書調の連打**は正確でも**読後が冷たく**、レビューとしての寄り添いが薄くなる。**です／ます**に加え、**〜ていく／〜してしまう／〜ですね／〜てくれる／〜感じられます** などを転換点や段落末に挟み、聴き手の体感へ一度フックを返す（**効果保証・医学診断にはしない**）。カミング標本は凛とした短句が多いが、ルート B はこれに**縛られすぎない**。見本：`kyoku-mugen-zekkyou-count-chikuni/index.md` のパート別解析。
6. **進行把握は正面から書く（再発防止）** … 長尺でも「どこまで進んだかがわかりやすい」といった評価は、**否定の二重（〜しにくい）**や抽象語「手掛かり」だけに頼らず、**読者が何を把握しやすいかを一文で言い切る**。  
   例：**×**「『どこまで聴いたか』の手掛かりが途切れにくい」→ **○**「今どの場面まで聴いたかが把握しやすい」。総評・グラフ・パート別いずれにも適用する。
7. **タイトル・パート名と内容の重複を避ける（再発防止・完成度）** … 「入眠用トラックだから入眠しやすい」「安眠だから自律神経が〜」のように、**商品側が既に約束している効果の言い換え**だけで済ませない。**読み手が実際に気にする落差**（高刺激の直後の急転換、角の立つSE、名目だけのパートなど）を一文で置き、**検証可能な音響・編集・勾配の事実**で返す。同人シチュボイスでは `src/content/記事/_同人音声執筆ガイド（仮）.md` の「タイトル・トラック名と重複する断言」を併読する。
8. **曖昧な便利語で段落を締めない（再発防止）** … 「挟みやすい」「入れやすい」「〜しやすいです」など**だけ**では、**何をどうするのか**（長尺のどこで休憩するか、分割再生の区切りとしてどう機能するか、音量やノッチをどう動かす目安になるか）が読み取れない。**聴き手の具体的な行動またはその記述の機能**まで書いて終える。実用メモ・グラフ・おすすめ・総評のいずれにも適用する。
9. **「主菜」比喩を使わない（再発防止）** … 献立メタは読みやすさを削ぐ。**軸・中心・土台・主眼・そのパートで前景になるもの**など平易語で書く。`summary`・おすすめ欄・パート解説・総評も含む。
10. **語感先行の言い回しを避ける（再発防止）** … 「いきなり尖らず」など、意味が読み手ごとに揺れる語感中心の表現は使わない。**何が急にならないのか**（刺激の上がり方、会話の温度差、SEの立ち上がり、終端への落とし方）を丁寧に具体化する。

## 4. 末尾ブロック：二ルート（作品感想／構造総評）

### 4a. `## 作品感想` ルート（ラブハピ基準・従来）

- **パート別解析で解析調に寄せたぶん**、ここでは比較・総括も含め **一人称の体験記**を可能な限り徹底する（§3a の文体ルールはパート別解析側に適用）。
- **冒頭・締めは正本どおり必須** … 「みなさんお疲れ様です。管理人です(__)」／「では、良き催眠ライフを👋」（読点どおり）。
- **管理人の敗北**を全体の**おおよそ 3〜4 割**まで上げてもよい案件では、正本の禁止事項（年収・年齢などの捏造）を守ったうえでドラマチックに書く。
- **関連リンクは §7 の「最後の一撃」に1本だけ**がよい。

### 4b. `## 総評：本作品の構造的結論` ルート（カミング標本）

**`## 作品感想` を置かず**、本文末尾を**論理総括**で締めるときの標準。**見出しタイトルは `総評：本作品の構造的結論` を推奨**（サイト実装上 h2 であればよい）。

**同人レビュー（シチュボイス）との分担（追記）** … 上記 h2・三柱は**催眠ルート B**の標準。同人向けの実用体裁は `src/content/記事/_同人音声執筆ガイド（仮）.md` に従い、総評は **`## 総評：本作品の結論`** と **`### 【設計の要点】`／`### 【音響面の精度】`／`### 【結論】`** の並びとする。**見出しに「（失敗しにくさ）」などの括弧ラベルを付けない**（内容は本文・箇条書きで書く）。

- **文体** … **三人称・断定**。設計論・機序・市場側の結論。**挨拶・絵文字締めは書かない**。
- **構成（標準三柱）** … h2 の直下に、次の **h3 をこの順で三つ**置く（**見出し文言は原則どおり**。特例で増減するときは `_分析データ.json` の `notes` に理由）。
  1. **`### 【設計の論理的総括】`** … 作品全体の **「狙い」** と **「手法」** を総括する（例：能動性を奪う、呼吸同期の徹底。**パート別解析の細目の繰り返しにしない**。ワンランク上の設計論）。
  2. **`### 【物理的干渉の機序】`** … **パート別解析の文章を短くしただけ・並べ替えただけの要約にしてはならない**。ミクロの「点」はすでにパート側で書いた前提とし、ここでは **「結局、この作品の最強のハックポイントはどこか」** を**一つに絞って提示する**。その一点（例：終了数字「ゼロ」を快感の開始信号へ再定義する、など）を軸に、認知資源の飽和・自律リズムの外部委譲・快感の起点の書き換えなどが **なぜそこへ収束するか** を**一本の線**で書く（医学診断・効果保証は書かない）。
  3. **`### 【結論】`** … この作品の **市場における立ち位置** を定義する（例：ドライの基準点、特定ユーザーへの解決策。**他作品名・他 slug は出さない**。比較は抽象レベルまたはジャンル語で足りる）。
- **総評三段の密度（添削・再発防止）** … 【設計の論理的総括】は「枠組み→主要手段（音・定位など）→議論がどこへ収束するか」を**一段落**で示し、パート見出しの列挙で済ませない。【機序】はパート別の要約ではなく、**命名できるハックを一文で宣言したうえで**、その一点が全体をどう束ねるかだけを**一本の線**で書く（終端語・カウントと快感の結びつけは §2 のタイトル断定と整合させる）。【結論】でベンチマーク・設計宣言など強い語を使うときも**他作品名は出さず**、「〜になりうる」「〜として読むのが妥当」「〜として評価するのが妥当」など**効果保証に読まれない語尾**に寄せる。**聴き方の前提**（ループ単体で切るとテーマとずれる等）は結論や `summary` の警告で触れてよいが、**おすすめで解除を売る**のは §2・おすすめ／合わない 項6 どおり避ける。
- **総評本文の装飾（太字の抑制）** … 【設計の論理的総括】【物理的干渉の機序】【結論】の**各 h3 直下の本文**では `**太字**` を**多用しない**。三つの見出しでスキャン区切りが既に付いているため、段落中の太字が**点々の強調**に見え、論旨の一本線が薄れやすい。`## パート別解析` や `グラフ評価内訳` で既に踏んだ手触り語を、総評でバッジのように繰り返す必要もない。**連続した断定調の散文**で因果を完結させる（§3e・キーフレーズの太字はグラフ欄など別ブロックで足りる）。**見本:** `unknown-hypno-daijobu-koe-ni-yudanete/index.md` の `## 総評：本作品の構造的結論`（2026-05 改稿以降）。
- **`### 最後の一撃`・関連レビュー1本** … **置かない**（標本に合わせる）。他 slug を本文に増やさない方針は正本と同じ。
- **購入導線** … サイト側で **`affiliateLinks` があるとき**、総合評価横の体験版ボタンに加え、**本ブロックまで読んだあと（`rest` 末尾）に「購入はこちら」が自動表示**される（実装はレビュー詳細ページ）。

## 11. 誘導/暗示の本文フォーマット（現行確定）

以下は当面の標準。後日改定までこの体裁を維持する。

### 11.1 評価対象と算出

- 作品ごとに都度算出し、過去作品の特性値を流用しない。
- 対象は原則「本編中心」。必要時は `注意事項`・`レクリエーション`・`解除` を除外して集計する。
- 数値化は次を固定:
  - 誘導構成比: 5カテゴリ合計 `10`
  - 暗示構成比: 7属性合計 `10`
  - 誘導特性/暗示特性: 各項目 `0-5` 独立評価
- 未使用要素は `0` で出力してよい。

### 11.2 本文セクション順（レビュー）

主要見出しは `jinsei-senpai-koi-dorei-mind-control` を標本として、次の順を基本とする。

1. `## 作品名`
2. `## 作品概要`
3. `## 作品評価グラフ`
4. `## 解析結論`
5. `## どんな人におすすめか`
6. `## 総合評価`
7. `## 本作の誘導・暗示解析詳細`
8. `## パート別解析`
9. `## 総評：本作品の構造的結論`

### 11.3 構成比テーブルの表記

- 列見出しは固定:
  - `項目`
  - `数値`
  - `読者が得る体験`
- 項目セルの技法表記:
  - カテゴリ名は `〜性` / `〜暗示` を維持
  - 技法は `【技法名】` で個別に分割して改行
  - `/` 連結は使わない

### 11.4 構成比の注記文（固定）

- 誘導構成比:
  - ここではどのような技法を用い催眠誘導しているかを可視化しています。
  - 解除パート等を除外した本編のみの比率です。
  - 数値は割合を表していて合計10になります。
- 暗示構成比:
  - ここではどのような暗示を用いリスナーに快楽体験をさせるかを可視化しています。
  - 解除パート等を除外した本編のみの比率です。
  - 数値は割合を表していて合計10になります。

### 11.5 特性ブロック

- 誘導構成比の直下に `### 本作で特に強い誘導特性` を置く。
- 暗示構成比の直下に `### 本作で特に強い暗示特性` を置く。
- どちらも「説明文 + ミニ表（特性/スコア/効果）」で統一する。
- パート引用（`>`）と誤認される表示は使わない。

### 11.6 推奨感度Lv

Lv規定は次で固定:

- Lv1: トランス感覚がまだ掴めない
- Lv2: 浅いトランスは可能（重感・脱力まで）
- Lv3: 中程度トランス＋暗示受容は可能（ただし絶頂反応は未形成）
- Lv4: 脳イキは可能だがドライ未達
- Lv5: 脳イキ・ドライとも可能（再現性あり）

表示ルール:

- 全作品で「体験可能レベル = 推奨レベル」を採用する。
- 本文では `推奨感度Lv` のみ表示する。
- 例: `推奨感度Lv：3以上（中程度トランス＋暗示受容は可能。ただし絶頂反応は未形成）`

### 11.7 文体制約（重要）

- 判定ロジックや内部運用のメタ説明は本文に書かない。
- 作品体験として読める表現を優先する。
- **パート番号だけ**（`01` `02` `06` や **`05 帯`** など）で区間を説明しない。**`### パートの長さ` と同じ正式パート名**で書く。尺一覧では販売表記に合わせ **番号＋パート名** の併記もよいが、その番号を**グラフ・おすすめ・パート別の実行文から裸参照しない**（詳細・ルート B の見出しは §1（補）項6・§3b「パート番号の本文参照」）。

### 11.8 概要ブロック（UI）

レビュー詳細上部に概要ブロックを置く。

- 概要内に `OUTLINE` を表示し、本文 `##` 見出しへのアンカーリンクを並べる。
- `作品名` と `どんな人におすすめか` は OUTLINE から除外する。
- 見出しリンク押下で該当セクションへスクロールできること。

### 11.9 二重チェック（ルート B・新規／全面改稿・再発防止）

**適用:** 解析フォルダ起点の**新規レビュー**、または**ルート B に準拠した全面改稿**を完了扱いにする直前に、**同一セッション内で二度**（執筆後→見直し）次を満たすこと。**エージェント／人間いずれも**、公開・ユーザー渡し前に機械的に走らせる。
