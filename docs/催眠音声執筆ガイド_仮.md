# 催眠音声執筆ガイド（仮）

**正本との関係:** 本書は `src/content/記事/_最強サンプルレビュー執筆ガイド.md` および `.cursor/rules/review-prose-voice.mdc` に**上乗せする改善案**の草案です。**2026-05 以降、催眠の「高密度パース・論理総括」ルートの標本は `futarigake-saimin-coming-orgasm`（カミング標本）**とする。体裁が正本の「ラブハピ一式」と二層になる箇所は、本仮ガイドの**カミング標本節を優先**し、ラブハピ基準ルートとの**併記**で読み分ける。

---

## 1. 目的（何のための上乗せか）

- 読者の**理性を論理でほどき**、**本能側の「聴きたい」**に接続する。
- 「作品が何をしているか」だけでなく、**聴き手の身体に何が起きうるか**を文章に織り込み、再現性のイメージを持たせる。
- ただし**医学診断・効果保証**は書かない。強い口調は**体験の宣告**として書き、必要なら**個人差**を一言で添えて誤解を避ける。

## 2. 冒頭：脳ハック処方箋（アイキャッチ直下）

**配置:** レビューページでは `summary`（YAML）が**表紙画像直下のカード内**に表示される。ここに、次の**3要素をこの順で**つなげたブロックを置く（段落分け可）。

1. **ターゲット（共感と看破）**  
   言語化しにくい執着・焦燥（例:「イかなければ」への縛り）を**短く言い当てる**。
2. **体験（生理的変化）**  
   定位・密度・リップ・呼吸同期など**音の組み立て**が、**どのように注意を奪い**、**どんな無力な快感**を立てうるかを、**宣告調**で書く（説明書の箇条書きにしない）。
3. **警告（不可逆性）**  
   聴いたあとに**これまでの自己処理が空虚に感じる**など、**中毒性／手放しの難しさ**を一文で提示し、読者に**選択の重み**を渡す（購入の免罪符＝「知っていた」ではなく**覚悟の共有**に留める）。

**注意:** `summary` に**解析手順・ファイル名・文字起こしメタ**を書かない（正本どおり）。

**標本:** `futarigake-saimin-coming-orgasm/index.md` の `summary` ブロック。

## 3. パート解説／パート別解析

### ルートの選び方（重要）

| ルート | 見出し | 向き先の例 |
|--------|--------|------------|
| **標準（ラブハピ基準）** | `## パート解説` | 販売コピー寄りの総論・手記的温度を **`## 作品像` → `## パート解説` → `## 作品感想`** で積む。 |
| **構造総括型（カミング標本）** | `## パート別解析` | **`## 作品像` を置かず**、総合評価のあと**いきなりパート別**。末尾は **`## 総評：本作品の構造的結論`**（下記 §4b）。 |

サイトでは `## パート解説` と `## パート別解析` は**同じ見出しスタイル**になる。名称は執筆上の宣言として使い分けてよい。

### 3a. パートブロックの基本方針（カミング標本＝本節フル適用）

1. **「解説」ではなく「解析」**  
   台本のあらすじにとどめず、**定位・呼吸・リズム・ミキシング**など収録から言い切れる**音響的事実**が、リスナーの注意と判断をどう再配分するかを**論理的に解体**する。
2. **因果関係の明確化**  
   **`〇〇という演出（音響的事実）` → `その結果、処理／判断がどう諦めざるを得なくなるか（論理のステップ）`** の順で書く。飛躍があるときは、中間ステップを一文足す。
3. **文体の統一（解析ブロック内）**  
   「私には〜と感じました」などの聞き手主観は**使わず**、断定の解析調を基本とする。**読みやすさ優先**の案件では §3e に沿って **です／ます体**でもよい（高密度パース・催眠向けにありがち）。**一人称の体験記は `## 作品感想` ルートにのみ**置く（§4a）。
4. **身体の反応の記載**  
   各パートの末尾に、聴取時に観測できた事実を **`身体の反応：`** で**一至二文**に収める（医学診断・効果保証は書かない）。読みやすさ優先なら**体言止め・名詞句**でもよい。

### 3b. 構成フォーマット（パート単位・カミング標本）

パート見出しの直下に**引用**（台本の根拠＝**演出の核**。別見出しや要約ラベルは置かない）を置き、そのあと **`**解析:**` → `**身体の反応:**`** を**この順で**並べる。

```markdown
### 00X [パート名]

> （該当台本の引用。必要なら複数行）

**解析:** （例：引用どおり左右の情報が詰め込まれ、定位の隙間から「保留」が削られる。その結果、理性側のブレーキより先にリズム側へ注意が固定されるという設計である。）

**身体の反応:** （例：波が返るたびに腰が反応し、思考より先に「次」を肯定させられる。）
```

**正本の `## パート解説`**（引用→解説が主体の記事）では、この **`解析:`／`身体の反応:`** ラベルは**必須ではない**。ただし論理解体が薄くならないよう、**§3a の因果の型**は参照してよい。

**技法名の括弧**は正本どおり**催眠誘導の手続きに限定**し、状態俗語を括弧のラベルにしない。

### 3c. 解析素材との突き合わせ

作業フォルダに同梱した **JSON・VTT・SRT・waveform CSV** など（例：投稿前チェック用の v2 一式）とタイムコード・波形を突き合わせ、**音響的事実を捏造しない**。リポジトリ内の `analysis/` と内容がずれるときは、掲載前にどちらを正とするか決める。

### 3d. 断定の置き場・音響的根拠（解析以外でも共通）

1. **強い断定は「効果保証」ではなく「作品クオリティ評価」へ**  
   「絶対にイける」などの**結果保証**は書かない。代わりに **構成・密度・音の運び**への評価として強気に言い切る（主に **`## 作品感想`**・**`## 総評：…`**・総括）。
2. **`summary`・グラフ本文の語り**と **パート別ブロック** の役割は分ける  
   前者は読後動機やスキャン優先の短文、後者は**理屈の透明度**優先。同じ文言を細分化して貼り付けない。

### 3e. 平易化の優先（添削で効いたこと）

内部機序を**細かく積み上げただけ**の長文化は、スキャンも理解も落ちる。**読者が一読で装置→効果を追える**ことを優先する。

1. **因果を短く並べる** … 「〜により」「〜することで」「〜によって」をはっきり置き、一段飛びを減らす。
2. **専門語にはひと言相当の説明を添える** … 引用符・括弧でよい（例：自律リズムの外部委譲、淡い快感での障壁除去、正のフィードバック）。
3. **解析と身体の反応の分担** … 解析はメカニズム／設計の意図、身体の反応は観測。**同じラベルを両方に重ねない**（副交感優位などはどちらかに寄せる）。
4. **強調記号は要点の短句だけ** … 長文全体を太字にしない（細かい運用は本文制作側で調整）。

## 4. 末尾ブロック：二ルート（作品感想／構造総評）

### 4a. `## 作品感想` ルート（ラブハピ基準・従来）

- **パート別解析で解析調に寄せたぶん**、ここでは比較・総括も含め **一人称の体験記**を可能な限り徹底する（§3a の文体ルールはパート別解析側に適用）。
- **冒頭・締めは正本どおり必須** … 「みなさんお疲れ様です。管理人です(__)」／「では、良き催眠ライフを👋」（読点どおり）。
- **管理人の敗北**を全体の**おおよそ 3〜4 割**まで上げてもよい案件では、正本の禁止事項（年収・年齢などの捏造）を守ったうえでドラマチックに書く。
- **関連リンクは §7 の「最後の一撃」に1本だけ**がよい。

### 4b. `## 総評：本作品の構造的結論` ルート（カミング標本）

**`## 作品感想` を置かず**、本文末尾を**論理総括**で締めるときの標準。**見出しタイトルは `総評：本作品の構造的結論` を推奨**（サイト実装上 h2 であればよい）。

- **文体** … **三人称・断定**。設計論・機序・市場側の結論。**挨拶・絵文字締めは書かない**。
- **構成（標準三柱）** … h2 の直下に、次の **h3 をこの順で三つ**置く（**見出し文言は原則どおり**。特例で増減するときは `_分析データ.json` の `notes` に理由）。
  1. **`### 【設計の論理的総括】`** … 作品全体の **「狙い」** と **「手法」** を総括する（例：能動性を奪う、呼吸同期の徹底。**パート別解析の細目の繰り返しにしない**。ワンランク上の設計論）。
  2. **`### 【物理的干渉の機序】`** … 各パートの **「点」（ミクロ解析）** を **「線」（マクロ機序）** で結ぶ。脳の **認知資源の飽和** や **自律神経への介入** が、**全体としてどう機能したか**を解説する（医学診断・効果保証は書かない）。
  3. **`### 【結論】`** … この作品の **市場における立ち位置** を定義する（例：ドライの基準点、特定ユーザーへの解決策。**他作品名・他 slug は出さない**。比較は抽象レベルまたはジャンル語で足りる）。
- **`### 最後の一撃`・関連レビュー1本** … **置かない**（標本に合わせる）。他 slug を本文に増やさない方針は正本と同じ。
- **購入導線** … サイト側で **`affiliateLinks` があるとき**、総合評価横の体験版ボタンに加え、**本ブロックまで読んだあと（`rest` 末尾）に「購入はこちら」が自動表示**される（実装はレビュー詳細ページ）。

## 5. 語彙の変換（説明→体験の宣告）

以下は**例**であり、作品ごとに置き換える。

| 説明寄りの言い方 | 体験宣告寄りの言い方（例） |
|------------------|----------------------------|
| 負担が軽い | 抵抗が先に無効化される／力まなくていいよう組まれている |
| 手順が追いやすい | 流されるままに段が積み上がる |
| 入りがよい | 入口で注意が奪われる |
| 深いトランス | 深さというより体感側に引きずられる（該当作品のみ） |

## 6. 正本と矛盾しないためのチェックリスト

### どちらのルートでも必須（サイト・データ整合）

- **`## 総合評価`** の `**グラフ評価内訳**` 形式、**絶頂行**（該当作品）と `_分析データ.json` の **`orgasmSummary` の形式一致**（`ドライ<整数>回（系統）／ウェット<整数>回`）。
- **採点メタ**（物差し独白、略号の羅列）を本文に増やさない。
- **心拍画像がない**作品に心拍見出しを捏造しない。

### ラブハピ基準ルートのみ必須

- **`## 作品感想`** の標準冒頭・締め（§4a）。
- **`### 作品解説と感想`** を **`## 作品像` 直前**に置く（サイトの総合評価カード分割用）。

### カミング標本ルートでの省略（意図的）

- **`### 作品解説と感想`**・**`## 作品像`** … **省略可**（総合評価の `---` の直後から **`## パート別解析`** へ）。
- **`## 作品感想`**・挨拶・良き催眠ライフ・**`### 最後の一撃`** … **省略可**（代わりに §4b の総評）。

## 7. 記事末尾：「最後の一撃」（作品感想ルートのみ）

**`## 作品感想` を書く場合**、感想本文のあと、`では、良き催眠ライフを👋` の**直前**に、`### 最後の一撃` を置いてよい。

1. **機会損失の提示** … 強気だが誹謗にならない一文で締める（脅迫・他者攻撃は禁止）。
2. **関連作品は1本だけ** … 当サイトの**過去レビューから1 slug**に限定する。

**構造総評ルート（§4b）では本章は適用しない。**

## 8. 正本への取り込み方（運用メモ）

本仮ガイドで成果が出たら、`_最強サンプルレビュー執筆ガイド.md` に**カミング標本としての節**が取り込まれているか確認し、差分だけ追記する。**ラブハピのトーンを第一正本として壊さず**、二ルートを**明示分岐**として維持するのがよい。
